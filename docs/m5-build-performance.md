# M5 构建性能与即时调参

本次交付将调参比较与完整构建分开：已有联合候选的发束、裙袖和挂饰可即时调整摆动幅度；最终 Spine 文件仍由完整求解和验证产生。

## 操作

1. 在动作编辑页载入联合候选，展开“联合动画”。
2. 保持“即时比较随动幅度”开启，调整响应强度或启停已生成区域；右侧结果窗口与动作时间轴同步更新。
3. 使用撤销或关闭即时比较，恢复原构建结果。草稿保存不会替换原候选；下载仍对应原文件。
4. 确定参数后构建联合候选，再检查和导出。构建区展示实际用时、当前阶段和最耗时的三个阶段。

即时比较缩放已经烘焙的辅助骨轨迹，不重新求解弹簧。刚度、阻尼、角度上限、挂点、发根固定范围、逐级跟随、表情和新增区域仍须构建。原强度为零、几何保护关闭响应或来源静止时，页面提示无法凭幅度缩放生成新运动。即时放大可能超出原候选几何保护范围，因此明确显示“未验证”，不沿用原 QA 结论。

## 实现与等价性

- 关键帧查找改为二分查找，保持原插值公式、相同时间处理及边界行为；随机和倒序采样有回归覆盖。
- 同一生成过程直接复用内存中的参考与几何检查，减少写出后再解压、重复检查；进入捕获时核验整包摘要、骨架摘要及几何报告字节。其他入口仍完整读取并核验参考分块。
- 分块写入按实际输出累计大小，减少完整参考的重复序列化；容量限制保留，正式资产字节不变。
- Python 到 Node 的大参考临时文件改用 gzip 1 级，正式资产压缩策略不变。Alice 143.95 MB 参考压缩由 6.283 降到 0.777 秒；代价是临时文件由 67.24 增到 104.57 MB。解压字节一致，256 MiB 解码限制保留。
- 浏览器每批处理 8 帧，减少跨进程调用；每帧仍重新应用姿态、真实绘制、读取 framebuffer。截图在对应帧内取样。
- 像素统计去掉逐像素 DOM 尺寸读取，透明度阈值仍为 8/255，边界像素计数保持一致。没有降低画布尺寸、帧数或检查范围。

最终 Alice、辉夜生成资产摘要与旧版完全相同；全部 4,362 帧结果、140 张截图摘要、setup 对照、绘制顺序及附件切换检查均相同。既有异常和缺测不变。这不是新的视觉批准，也不说明旧候选已不存在技术问题。

即时幅度比较另用官方 Spine Core 4.3.13 检查：Alice 第 6 秒，强度 1/0.5/0 相对原结果最大顶点变化为 0/0.947/1.895 px；非随动骨局部轨迹不变，6→2→6 跳帧和关闭预览恢复误差均为零。纯幅度计划与应用的中位耗时约 0.021 ms，不含界面、资源加载、绘制或完整求解。
