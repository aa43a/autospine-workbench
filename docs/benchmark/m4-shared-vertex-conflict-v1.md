# M4 共享顶点面积约束冲突

日期：2026-09-27。状态：确定一个局部不可解反例；修正候选仍未采用。
接续 [正常区域保护](m4-parent-setup-area-v1.md)。

## 新证据

Alice 左腿约 0.605208 秒，三角形 314 与 323 共享可移动顶点 196，其余顶点
分别固定在 calf、foot 的当前补偿表面上。两个面积下限都对同一顶点形成线性
半平面约束。将面积梯度归一化后，把两个不等式相加；任意预算内的位移满足：

`(n1 + n2) · displacement ≤ budget × |n1 + n2|`。

实际要求的右侧下限约 **6.217467**，允许位移圆盘上的最大值约 **4.187091**，
差约 **2.030376**。这里是两个法向位移投影之和，单位为像素，并非直接要求
顶点移动 6.22 像素。已计入原最终面积容差和保守浮点余量。

因此，在当前固定边界、面积要求与 15.607425 像素预算下，这两个要求无法
同时满足。不是单纯增加迭代次数就能修好；该反例不证明其他姿态或其他绑定
策略均不可行。约 0.731250 秒没有检出同类必要条件反例，也没有找到通过解。

来源父包仍为
`2424c43da460100d70b0c4d43ef380da86b999fd8daa8beba04e98480005479c`。
落盘证据：`tmp/m4-transverse-batches-v1/shared-vertex-counterexamples-v1.json`。

## 实现

- `single_vertex_area_feasibility` 检查共享唯一可移动顶点的面积下限，返回
  两个三角形、顶点、法向量、预算与缺口。没有反例不能冒充全局可解证明。
- `fixed_boundary_area` 检查固定封闭边界内的总面积必要条件。当前真实问题的
  活动区域具有可动外边界，因此该检查没有给出证明，未将其误报为不可解。
- 局部优化报告增加面积缺口、边长超限、预算余量、固定点位移和优化器消息。
  明确区分优化器成功终止与独立约束通过。
- 增加可选的可行性优先求解。真实两姿态仍未通过，不覆盖原始点；单元测试
  专门验证“优化器 success=true、约束却失败”不能返回可接受候选。

## 对照与方向

独立试验还保留了末端 foot/hand 影响的已有世界位置修正，保持骨骼映射和权重
不变。这是显式 `anchor_terminal` 实验选项，默认关闭。
`tmp/m4-transverse-batches-v1/terminal-anchor-probe-v1.json` 证明仅保护脚端仍
不能解决 0.605208 秒反例：所需下限约 6.249612，允许上限约 4.211627。
因此不能把这个选项作为修复自动接入生产。

下一步应调整 calf 到 foot 之间的补偿边界或局部补偿范围，使其具有可行的

改写用户绑定、放宽门槛或用优化器成功标志掩盖约束失败。
