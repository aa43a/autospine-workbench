# 分片与裁剪的独立 Runtime 重构核查

2026-09-22。结论：旧连续凹逆裁剪候选不具备采用条件，工具已拒绝继续生成。连接片局部视觉改善不能抵消裁剪导致的像素缺失。

## 核查方法

`check-m4-material-reconstruction.mjs` 从身份核对后的两侧 scene 读取源纹理与候选，使用相同官方 Runtime、相机、采样时间、过滤和透明 framebuffer 分别绘制：原始手臂；仅材料分片；材料分片加原凹逆裁剪。只移除无关槽位，不更改原骨骼轨迹或手臂 deform。直接比较 GL 返回的预乘颜色与 alpha，避免把透明 RGB 当作可见差异。

删除连接片作为负对照，在 1.05 秒产生 1,468 个差异超过 8/255 的像素，含 1,065 个不透明像素缺失，确认检测确实能发现缺失。原始帧图、scene/runtime 摘要和采样结果均存档。

## 发现

- 198 个时刻（区间内部及切换前/时/后）：仅材料分片最大 alpha 差 58/255，没有不透明像素缺失；仍不可称作精确重构。
- 同次检查原凹逆裁剪最多丢失 596 个不透明像素，发生在约 0.7 秒。它们此前被整角色躯干或局部相机范围掩盖。此前 1.05 秒单像素结论仅适用于当时 ROI 和切换比较，不能描述完整裁剪质量。
- 本机官方 Runtime 4.3.13 的 `SkeletonClipping.clipStart` 在 inverse 模式下调用 makeConvex；ClippingAttachment 的类型说明也明确 inverse 始终使用凸裁剪。普通凹裁剪保留凹形，逆裁剪却排除凸包，两者不互补。原矩形能力验证未覆盖此情况。

代码来源为本地官方依赖 `tmp/spine43-verification/node_modules/@esotericsoftware/spine-core/dist/SkeletonClipping.js` 与 `attachments/ClippingAttachment.d.ts`；实际加载的 runtime 摘要记录在同名 JSON。未修改官方 Runtime。

## 已做修正与替代验证

新增 `m4_clip_inverse_guard.py`：拒绝凹形、退化及自交星形输入，支持合法共线边与两种绕序。真实旧候选已触发 `inverse_clip_concave_runtime_convexifies`。凸关键帧通过不代表插值连续时间已获证明。

从同一源深度场提取显式后方区域：49 个多环时刻、50 个单环时刻、142 个空区域时刻。使用前/后各自普通裁剪，在 241 个源帧及中点逐一构造独立静态 skeleton：不透明像素缺失峰值从 596 降为 0；23 个时刻仍有超过 8/255 的差异，每帧最多 2 像素，最大 alpha 差 109/255。阈值只是差异描述，不是放宽后的验收线。

这些是逐姿态验证，不是一个连续可播放动画。还需处理后方组件出现/消失、轮廓对应和时间插值。候选仍未采用，暂不推广三角色。材料过滤误差与裁剪误差分别保留。

现有隔离预览已添加不可采用提示；旧候选字节、报告和原人工记录保留。目标 Spine 4.3.26 与实际捕获 Runtime 4.3.13 分开记录。
