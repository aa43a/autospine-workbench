# M4 一致表示与存储精度检查

2026-09-27。补充原 normalized-audit 的精度归因，不修改候选或验收门槛。

工具新增三种明确的参照方式：source-origin 保留旧行为；normalized-origin 对
补偿参照执行与候选相同的时间别名转换；runtime-storage 再将父包、补偿、
候选全部按官方解析器支持的 Float32 存储模型转换。实际导出骨架与用于
数值计算的骨架分别记录摘要，不覆盖此前报告。

## 结果

- normalized-origin：16,557 时刻全部通过，固定点差异 0。此前 12 个固定点
  微小差异来自候选与参照使用不同时间表示，原 source-origin 失败仍保留。
- runtime-storage：30,232 时刻（保留旧时刻并加入存储时间键间采样），其中
  27,394 时刻面积下限失败；20,390 时刻涉及相对已压缩父包的微小退化。
  固定点差异仍为 0，原正常区域失效 0，最大边长比约 1.920628。
- 对每 100 个失败时刻抽取一个作进一步诊断，共 274 时刻、5,497 条三角形
  记录：抽样最大面积比例缺口 8.922560e-6，固定区域最大 3.656345e-7。
  这些是抽样极值，不能作为全集误差上界。

因此 CPU 双精度通过不能替代实际存储精度的几何保护。下一步需要将精度
误差纳入求解与独立检查，尤其固定区域不能靠释放顶点或放宽门槛掩盖。
不能从数值缺口很小直接推断整角色视觉可接受；原 setup 压缩问题仍存在。
