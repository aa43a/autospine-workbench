# 下蹲三维表面参考：来源检查

2026-09-24。为解决大幅 Squat 的膝部读向和轮廓问题，检查真实 FBX 是否可以提供蒙皮表面参考，而不是再次仅优化二维骨架或重复 ARAP 参数试验。

## 当前证据

- 固定集 overhead_squat.fbx，SHA `596014069e4ecc8527ba37feded9d7b8564d50832862dad89c0a75ca7c136bba`，实际 Blender 导入只有一套 53 骨架，网格数量为零。既有 source-category-sheets 也是骨架图，不是模型轮廓。
- 同一用户动作库中的 `mixmao角色/mixamo角色/Beta.fbx` 包含三片有效蒙皮网格，均绑定其唯一骨架。顶点数分别为 10514、11588、2510。模型 SHA `fd892dd062b815029539084255d75c19cbc54e5f68536641411865c35ef25af8`。
- 两者有 53 个同名骨骼，但 53 个初始矩阵都不同。大腿初始旋转差约 1.58°，小腿约 1.69°；全骨架最大初始旋转差约 17.18°。不能把同名映射当作直接复制全部动画通道的依据。
- 骨架对象矩阵一致，腿段长度比接近 1，说明这是可继续检验的参考，而不是已确认不可用。需要校准初始姿态差异，并独立核对源关节方向、时间和支撑位置。

工具 `tools/inspect-motion-surface-reference.py` 在 Blender 中独立重置场景、读取源动作和参考模型，核对源文件哈希未改变，记录骨架父子关系、局部初始矩阵、旋转差、骨长比和网格绑定。输出已存在时拒绝覆盖。实际运行 Blender 5.2.1 LTS，结果在 `tmp/squat-source-surface-v1/{inventory,beta-compatibility,beta-rest-orientation}.json`。

## 下一验证

先将同一 Squat 的起始、最低、起身姿态重定向到参考模型，明确补偿初始旋转差，不直接复制全部局部通道。逐时刻记录与源骨架的差异并检查支撑，再生成固定相机下的蒙皮轮廓。只有参考本身通过这些检查，才能用于二维姿态修形的对照。

参考模型外观不属于红美铃、Alice 或辉夜；它不生成这些角色的侧面纹理，也不替代目标 Spine 接缝、遮挡和视觉验收。当前没有新目标候选或新的动作接受记录，M4 六案例和三角色八类动作门槛不变。
