# M4 大候选异常定位复用

2026-09-25。真实候选 `75bf510d6b41ac578463dbe18d4ac784fc175c9a0739dea19969fd988f45104c` 的异常定位每次请求重复完整计算；该入口也被保存处理草稿与素材任务包使用。

新增进程内有界 LRU，最多四份报告、合计 32 MiB。命中前仍走现有 job context 与不可变仓库内容验证，只复用以 artifact 身份索引的诊断 JSON 字节；不缓存来源校验、人工决定或异常处理状态。异常和超大响应不缓存，同一进程冷计算串行避免重复工作。进程重启后重新计算，无磁盘旧版本缓存。

`tools/m4_geometry_cache_benchmark.py` 对上述真实 artifact 的两次读取均先执行 store.read：

原始测量：`localset/tmp/m4-motion-center/view-handoff-real-v1/geometry-cache-benchmark.json`。26 项测试覆盖缓存并发、身份隔离、条目/字节容量、失败不缓存、每次请求重新校验来源，以及既有诊断、处理草稿与任务包回归。

## 首次定位的范围收敛

活动附件分析原来对每条失败记录重新序列化整角色所有部件的逐帧顶点，固定附件定位器实际只读取当前记录对应的槽位。现在仍先执行完整场景的活动附件与几何检查，然后只把当前槽位的顶点交给单记录定位器；保留所有时刻、原骨骼、网格、纹理、附件身份和失败记录。

同一真实候选重新启动冷缓存进程测量：内容校验 1.485 秒、诊断 40.135 秒，首次合计 41.620 秒；重复合计 1.597 秒。相对上一轮首次 100.582 秒下降约 58.6%。报告仍为 595,489 字节、13 条记录，SHA-256 与优化前完全相同。测量文件为 `geometry-scoped-benchmark.json`，仍不代表浏览器端到端耗时或视觉质量通过。

新增多附件失败回归，确认其他部件的失败、全部相关帧和原始文件不变。首次约 42 秒仍不理想，当前没有减少检查或把初次计算时间隐藏为通过。

## 只读采样避免重复深复制

继续对同一候选做 CPU 分析，带分析器的总耗时约 129 秒，其中深复制累计约 53.5 秒；该分析器耗时不能与普通运行直接比较。内部 affine 采样器只读取骨骼、网格和动画数据，现在内部路径复用这些数据。公开的 `active_document` 仍返回完全独立的文档，`sample_active` 返回的坐标和三角形也保持独立，避免调用方改动污染源候选。附件选择、float32 边界、deform 校验与全部采样均保留。

未启用分析器的实际冷读取降为 31.898 秒（内容校验 1.555 秒、诊断 30.344 秒），重复读取 1.584 秒。报告字节数、13 条失败记录和上述 SHA-256 均不变。测量见仓库 `tmp/geometry-readonly-benchmark.json`；它仍是存储与诊断耗时，未测浏览器端到端延迟。首次约 32 秒仍需改进，不据此宣称性能目标完成。

40 项测试覆盖附件切换、稀疏 deform、身份与几何检查、定位及缓存；新增用独立规范化文档采样作对照，在切换前后及骨骼旋转/平移时比较完整返回值，并主动修改返回坐标和拓扑，验证源数据不变。

真实候选全部 2,234 个参考时刻与 `dd7eaa7` 采样器逐项比较，完整返回值严格相等，源文档未变。旧采样总计 26.266 秒，新采样 15.945 秒；这是 CPU 采样对照，不是重新运行官方 Runtime。工具新增 `--baseline` 与 `--all-reference`，证据为仓库 `tmp/active-readonly-all-samples.json`。Reach/Squat 质量状态保持不变。
