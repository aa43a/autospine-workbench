# Squat 肩部覆盖坐标与裙旁像素归因

2026-09-25。以已完成几何/Runtime 检查的 Alice `418038c3621a71b2a56893f53862b0611ce1feb7e0b232f75e786d09ff29dcb2` 为来源。没有改动此候选、像素或旧接受记录。

## 肩部覆盖

旧肩部区域约束用 chest 骨矩阵搬运源接触区域，但这版候选的躯干偏斜已经烘焙在 attachment deform 中，骨矩阵并不等于衣服材质的实际变换。约 0.964584 秒时，两袖覆盖支持位置的差异分别达到 **50.103 / 53.239 px**。这证明约束坐标不一致，不证明全部可见空隙都由此造成。

新增 `material_affine_frame.fit` 根据同一材质的 setup 和实际顶点恢复变换。必须所有顶点拟合误差 ≤0.00001 px 且不退化、不翻转；柔性或非仿射材料明确拒绝，不用拟合结果冒充精确接触。实际 topwear `layer-006` 的拟合误差约 8e-13 px。

`m4_owner_material_contact_probe.py` 验证所选衣服确实覆盖全部源接触像素，再将该材质变换用于区域约束。保留披肩覆盖袖子、可以滑动的语义，不改成整边缝合。当前是显式选定时间和覆盖层的诊断工具，尚未替换正式流水线。

同一姿态试算：

- `layer-003`：可行候选，最小面积比约 0.505，无翻转，最大边长倍率约 1.995，最大移动约 73.326 px。
- `layer-004`：仍未找到可行解，接触区域比约 1.454，面积与边长也超限。失败解不写入候选。

这不是整段动画通过，也不是 Runtime 或人工视觉验收。求解器返回的可行性依据是约束值，优化器状态仍为 false，原始字段保留；使用的工作树求解器摘要已写入证据，未提交其他在研求解器改动。

## 裙旁浅色区域

在官方捕获第 1920 帧（约 0.964584 秒）选择三个明确像素，经同帧 mesh/UV 追踪：浅色内容来自 **layer-001-l 左腿**，其后/前相关裙装 texel 的 alpha 为 0。两个腿部样本 alpha 为 255；第三个为 22。

查看实际 `images/layer-001-l.png` 可见它是腿部有效素材。因此这是腿部投影露出裙摆轮廓的问题，不能当作残余删除，也不能靠绘制顺序遮挡透明的裙装区域。三个最近纹理采样只用于归因，不是整块区域的像素级 GPU 等价证明。

后续需要处理肩部另一侧的可行性，以及侧身时腿与裙摆的可见轮廓关系；保持双腿/裙腰已验证结果，不能用它们的几何通过代替整体视觉通过。

证据：`m4-squat-material-contact-2026-09-25.json`、`m4-squat-detached-pixel-trace-2026-09-25.json`。本轮 8 个针对性测试通过。
