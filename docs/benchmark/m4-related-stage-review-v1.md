# M4 改进候选同页阶段验收

2026-09-26。改进候选此前可以播放、下载，新的人工阶段反馈却只能由脚本附在登记材料中。
现在在工作台的同一个改进候选面板提供“记录 / 查看阶段验收”，支持保存、读取和撤销，
并把对应记录加入下载包。本切片补齐操作链，不宣告大动作表现或 M4 已完成。

## 使用入口

打开 `http://127.0.0.1:8918/motion-cohort.html?pack=m4-fixed`，选择动作和角色，
展开“查看已关联改进候选”。每项显示候选短标识和证据登记短标识，避免同一候选的
不同复测版本混淆。可在当前页面加载时间轴，再读取并记录阶段结论。

- “当前版本的检查范围”列出限定采样通过、需处理和尚未验证的项目。
- 有异常或未测项时，“阶段可接受”不可选；可以填写具体范围后记录
  “阶段可接受，保留异常”，或选择“需要调整”。不会自动替用户勾选检查确认。
- 保存后立即显示新结论和历史；撤销追加一条记录，保留此前结论。
- 下载该项包含当前验收快照及全部历史，同时保留不可变候选、Runtime 和登记依据。

## 身份与历史

新接口为 `GET/POST /api/motions/{job}/related-candidates/{registration}/stage-review`。
写入要求同源、意图标头及准确的登记、候选、证据摘要和期望修订号。并发保存只允许
一项追加成功；另一项明确返回版本冲突。大文件校验在共享任务锁之外执行，写入前
重新核对当前任务来源。来源变化、损坏的纹理、错误登记或旧证据不能被确认。

日志独立保存到 `related-stage-reviews/{registration}/review-####.json`。已有
`stage-reviews`、候选文件和登记材料不改写。同一候选新增复测登记后，新日志从零开始，
不会继承另一登记的接受。登记时已有的人工视觉反馈保留为历史资料；新入口的结论
单独展示，撤销后也不会重新从历史资料中回填“接受”。

下载新增 `related-stage-review.json`，其哈希列入 `related-export.json`；后者同时记录
登记标识和验收修订号。原候选文件清单仍能恢复原始内容地址。相关结论始终保持
`production_authorized=false`，不会提升基线的通过数或替换原任务。

## 检查口径

复用现有 Motion Readiness 汇总精确候选内的证据。已有脚端复测只证明对应的 CPU
踝部支点采样，不等同鞋底接地；局部假设布面定位不作为完整遮挡通过。

真实数据核对：Alice Squat 的三个登记共享候选 `418038c362…`，其中两项有脚端复测，
一项还保留裙腿局部定位。几何与 Runtime 通过，完整投影和遮挡未测全，仍为
`evidence_incomplete`。Alice Reach 的 `31ccd0a841…` 保留用户原有的限定范围接受记录，
新入口不会把该历史反馈扩大成所有技术检查通过。

## 验证

45 项相关 Python 测试通过，覆盖真实不可变测试素材、追加/撤销/恢复、两个同时保存、
来源竞争、损坏候选、证据过期、跨登记隔离、同源请求和完整导出恢复。
9 项 Node 测试通过，包含六项本次界面逻辑测试及三组现有摘要/同步检查：
选中的播放器、表单和下载都指向同一登记；改进版验收事件不会改写固定基线统计；
晚到的旧摘要不会覆盖保存后的状态。

`tools/m4_related_review_audit.py` 可对真实工作台执行只读检查：读取阶段接口、关联清单、
播放器外壳和下载包，校验每个导出文件哈希，再比对基线与日志未改变。
