# 肩部紫色散点：源透明度归因

2026-09-25。上一轮按原始 PNG 显示记录了肩部、腰侧散点。本轮先核对实际 framebuffer 的 RGBA，再通过同一候选、同一时刻的网格与 UV 追溯源纹理，避免把低透明度颜色误判成新网格空洞。

在已捕获的 0.37496764957904816 秒，选择三个明确像素中心：(314,377)、(429,393)、(435,412)。三者 framebuffer RGBA 均为 (255,128,255,2)，都由 layer-006 上衣源纹理覆盖；源双线性透明度分别约 2.0381、2.0056、2.0/255。未发现这些位置由新网格空洞导致。

按 PNG 非预乘 RGBA 正常合成至 RGB=(32,32,32) 背景，结果约 (33.749,32.753,33.749)，通道差异不足两个灰度级。不能把原始 RGB 中的亮紫色直接当成不透明可见瑕疵，也不能因此扩大网格或强制缝合披肩与袖子。

这是三个像素中心的来源证据，不代表整片边缘已经检查。CPU 理想顶点及源纹理双线性采样也不充当 GPU 所有过滤条件的证明。裙侧露出的腿部轮廓仍是未解决项。

新增通用只读工具 `m4_framebuffer_pixel_trace.py`，要求候选、参考时间、截图哈希匹配，输出源图像哈希、三角形、UV、四个邻近源像素及背景合成值。测试覆盖低 alpha 原像素追溯和篡改截图拒绝，两项通过。

证据摘要为 `m4-edge-pixel-provenance-2026-09-25.json`。原观察记录保持原样，新增 `tmp/m4-moving-workbench/alice-squat-material-interval-runtime-v3/visual-observations-v2.json` 并记录其前版本哈希；只将散点结论收窄为“部分解释为源透明度”，不自动接受候选、不删除纹理、不修改骨骼或权重。

下一步集中处理实际蹲姿腿部材料在裙侧的轮廓与遮挡，不围绕这三个低透明度像素继续调整绑定。
