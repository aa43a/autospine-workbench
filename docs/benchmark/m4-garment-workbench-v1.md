# 裙腰跟随接入工作台（2026-09-26）

将上一切片的声明骨链根部位移算法接入动作中心的异常处理草稿、独立任务、进度与结果对照。
入口为“编辑衣料跟随、覆盖与前后关系”→选裙装附件→加载处理草稿→“裙腰随躯干投影跟随”。
无需先出现几何失败，服务器会从原角色裙装声明解析适用范围，不接受客户端指定任意骨链。

## 已交付行为

- 只读预检核对当前候选、原角色、裙装声明、实际应用的躯干投影、检查时间和受影响附件。
- 保存冻结草稿后可构建独立候选；提交时和执行时重新核对来源。大包读取在队列锁外完成，
  取得锁后再次核对草稿，避免撤销或更新期间提交过期计划。
- 整段动作只修改所选裙装的 deform，保留原骨骼动画、权重、UV、图片、绘制顺序及其他附件轨道。
- 重算相同时间网格下的整角色几何、踝部接触与裙腰材质点分离；下游仍调用既有遮挡和 Runtime 检查。
  未获得的新证据不沿用父候选通过状态。任务可按既有队列取消或重试。
- 当前不叠加第二次同类修复，也不隐式操作离线关联候选的基线。原候选与阶段验收记录保留。

## 包体与兼容性

首次辉夜输出超过现有 256 MiB 包体上限，暴露了真实构建阻塞。
现使用 `autospine.character-reference-chunks/v2` 对数值参考分块做 gzip/base64 无损压缩，
每块和解压内容均有摘要、长度及资源上限校验。骨架、纹理、关键帧、坐标精度和 QA 门槛不变。
原平铺格式和 v1 分块仍可读取。四个最终包均在现有单文件 64 MiB、总计 256 MiB 限制内。

78 项 Python 测试、9 项 Node 测试通过，覆盖范围包括来源失效、范围冻结、草稿撤销、
队列分派、保留其他部件失败、压缩损坏/膨胀拒绝、合同兼容、摘要以及下载 ZIP 完整往返。
前端测试仅检查组件逻辑；工作进程测试中的捕获被替换为测试桩，不算实际 GPU 验证。
