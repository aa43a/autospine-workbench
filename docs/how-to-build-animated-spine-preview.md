# 在主工作台构建可变形 Spine 动画候选

本指南面向已经准备好 See-Through audit 的项目；未登记项目先使用[准备动画来源](how-to-prepare-animation-inputs.md)入口生成辅助关节草稿。
完成一次源登记后，普通操作者可以在主工作台构建、播放、复核关节与绑定、重建并下载候选，无需填写 SHA 或寻找中间文件。

当前输出固定为 Spine **4.3.26**。这是已有 audit 的受限动画候选闭环；首次 Pose 推理已接入来源准备，任意 PNG 自动分层和首批十角色自动采用校准仍属于后续工作。
Alice、铃仙、琪露诺是当前已登记的三个开发样本；登记数量不代表三个样本的完整视觉质量已经通过。

## 构建并查看候选

1. 启动本地服务，打开主工作台，选择一个已经登记动画来源的项目。
2. 找到可变形动画预览区域。未登记的初始项目点击“准备动画来源”，完成后复核全部关节；已有离线审核数据仍可按下方方式迁移。
3. 选择“轻柔屈伸 · 15°候选”或“屈伸检查 · 30°候选”，点击“构建动画候选”。
4. 等待解析项目、构建网格、编译动画等步骤结束。状态查询只读取进度，不重复启动编译。
5. 在页面播放或拖动时间轴，查看异常清单，使用“下载动画候选 / QA”取得 ZIP。

有预览可下载时，运行仍为 `needs_review`。这表示候选可检查，不表示所有图层已绑定、接缝通过或结果获准发布。
两个片段都是两秒的有限四肢屈伸检查；不是已经验证的 walk、run 或完整角色动作库。

主页面播放器根据 CPU 采样的顶点绘制原纹理，标记为“诊断播放”。**它不是官方 Spine Runtime。**
包内 `qa.json` 的 `runtime_status: not_run` 不因页面播放而改变。官方 Runtime 检查必须另行运行，并绑定这个新包的精确身份。
旧翼片、接缝或四肢实验的 Runtime 通过记录不能替代新包的检查。

## 在同一页面修正关节

展开“关节复核 · 画布拖动”，点击“加载全部关节点”。页面一次加载全部十七项：
root、pelvis、chest、neck、head，以及左右 shoulder、elbow、wrist、hip、knee、ankle。

- 在图上选择并拖动可观测点，或明确确认当前关节。
- 无法判断位置时选择“不可观测”并填写原因；不应凭猜测填点。
- 只修改说明不会把所有模型建议自动标记为已复核。页面保留已有的明确复核记录。
- 使用“撤销关节修改”放弃尚未保存的修改，或点击“保存关节复核并重建”。

也可点击“自动检查关节点”，检查缺失／非有限／越界坐标、父关节缺失和零长度骨段；检查本身不会修改已复核列表。
看过全部点并修正异常后，点击“我已检查：一键确认有效点并重建”，一次确认结构检查通过的可观测点并保存、续跑。
不可观测或尚未标注点不会被批量猜测为已确认；结构检查通过也不证明人体位置准确。批量确认属于操作者明确的模型辅助复核，不是 `policy_auto`，也不批准图层绑定或发布。

若按钮全部灰色且提示此前同步的 `neck` 等校正被移除：选中该关节，核对 X/Y，点击“确认当前关节坐标”（数值未变化也可确认），再点顶部“保存校正”。主图层的“确认语义、Pivot 与目标骨”不会确认关节坐标。
如果同时提示图层目标骨变更不支持同步，误改时可选中该图层，点击“撤销本图层目标骨校正”；此操作仅移除候选骨覆盖，保留该层其他校正及所有关节点，保存后才能生效。如有意保留该换绑，仍需等待对应绑定迁移支持，不应为解除阻塞而撤销有效选择。
处理后点击“同步已保存校正并重建”，再回到本区复核。旧保存版本继续保留。

保存的标注始终为 `model_assisted`，`independent_annotation` 为 `false`；原始 Pose 观测和独立 GT 不被覆盖。
尚未复核全部点或存在不可观测点时，允许保存，但当前标准骨架编译保持阻塞，并说明需要补充什么。

**关节几何变化后，旧的 bind 选择退回 pending，需要重新检查绑定。** 原选择作为迁移建议提供，旧版本仍保留。
仅备注变化且骨架几何与状态不变时，已有绑定选择可以保留。显式排除、需要拆分等不依赖新骨架位置的决定不会被伪造为 bind。

这里的关节工具专门编辑已登记的辅助标注链。也可以先在主画布修改关节并点击顶部“保存校正”，再到**可变形动画候选预览**区域点击“同步已保存校正并重建”。上方“构建 Spine 预览”仍是静态 Region 工作流，不是动画的必经步骤。

保存作者修订后，动画来源先标为过期；恢复入口显示本次可导入的关节和不支持的修改。同步只读取已经明确保存的同名关节坐标，不用作者页面的自动 bbox 点覆盖辅助标注；未修改的点保留。眼睛等当前骨架不使用的关节仍保留在作者校正中，并在同步摘要说明。几何变化使旧绑定退回待复核，随后重建候选。

同步生成有来源记录的新登记版本，旧登记和作者修订不被改写。图层语义、拆分、可见性等尚不能迁移的修改会列出具体阻塞项；删除此前同步的关节也不会自动恢复成推断点。再次同步只导入相对上次同步发生变化的作者关节，避免覆盖之后在动画复核页保存的新位置。

## 处理绑定、分区和剩余异常

绑定复核显示完整草稿和当前骨架支持的选项。按图层选择绑定或标记待拆分、语义复核、排除，填写必要说明后保存。
保存成功后会重建相关候选；保存期间或存在未保存修改时，旧下载与构建操作受到保护。
两位操作者基于同一旧输入同时保存时，只允许一个版本提交，另一个需要刷新后再检查。

当前生成规则保留这些区别：

| 结果 | 页面与包中的含义 |
| --- | --- |
| 临时三骨建议 | 仅用于预览的假设，原草稿仍为 pending，不变成自动采用决定 |
| 通过当前几何采样的 Mesh | 可以播放，仍需网格和跨图层接缝复核 |
| 不通过几何检查的 Mesh | 不作为活动加权网格输出，保留刚性参照并列明原因 |
| 未绑定图层 | 保留原纹理作为明确的刚性上下文，不宣称完成绑定 |
| 左右分区和 residual | 有独立归属异常；不强制把所有剩余像素归给最近骨骼 |
| Runtime、接缝和遮挡 | 独立未完成项，不因其他检查通过自动清除 |

## 下载、取消与恢复

ZIP 包含运行时 skeleton JSON、atlas、纹理，编辑器用 `editor/skeleton.json` 与对应 images，以及 motion、QA、预览清单和 CPU 播放采样。
导入 Spine 编辑器时保留目录结构，使用 `editor/skeleton.json`，避免图片路径丢失。

可以取消构建。已运行的纯计算步骤可能先结束，服务会在步骤边界检查取消与输入漂移。
再次构建相同输入可以复用已经验证的网格或预览检查点；输入或编译器身份变化会产生新的运行身份。
浏览器刷新后重新点击构建即可查询或恢复当前输入，不必伪造作者 revision。

大体积 `playback.json` 使用动画包存储：单文件最多 64 MiB、整包最多 256 MiB。
它不使用小型运行日志的 128 KiB 限制；超预算会明确失败，不静默截断帧或图片。

## 常见阻塞

| reason code | 处理方式 |
| --- | --- |
| `animated_source_missing` | 初始项目点击“准备动画来源”；已有离线审核数据由维护者登记 |
| `animated_source_mismatch` | 检查 audit 内容、图层顺序及实际图片是否和登记来源相同 |
| `animated_source_stale` | 已保存作者修订时使用“同步已保存校正并重建”；若修改不支持迁移，查看恢复入口列出的具体阻塞项 |
| `animated_source_rebase_required` | 初次登记要求未修改作者 revision；当前不支持自动重基已有作者编辑 |
| `joint_review_required` | 在本区域复核关节；保留不可观测状态，不伪造位置 |
| `animated_review_conflict` | 有更新的复核版本；刷新后检查差异再提交 |
| `animated_no_eligible_mesh` | 当前素材没有通过这条受限链的活动网格，检查绑定、拆分与网格异常 |

## 维护者：一次性登记现有来源

此步骤迁移已有开发数据，不是普通用户每次构建都需要执行的操作。应使用同一角色的 audit 与已封存绑定草稿。
登记会精确校验源闭包并复制 audit 资源到正常项目发现目录；不会把 pending 记录改成批准。

在仓库目录执行，例如 Alice：

```powershell
$env:PYTHONPATH = (Resolve-Path .\src).Path
python -m autospine_workbench.automation.animated_cli --workspace .. --state-root workspace register alice `
  --manifest docs/benchmark/manifest-frozen-v1.json `
  --draft ../tmp/r2b-multibone/alice-defaults-confirmed.json `
  --audit-directory ../tmp/benchmark-development-audit-2026-09/alice
```

其他项目显式提供自己的 manifest、草稿及 audit，程序不按角色名称硬编码目录，也不按修改时间猜测“最新批准”。
已有项目的 audit、实际图像和未编辑 checkpoint 必须匹配；源登记不构成发布授权。
