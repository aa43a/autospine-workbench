# 动作构建性能

实时预览只求当前姿态。完整构建还会检查整段动画、求解局部网格修正、增加插值采样、跟踪脚端、检查遮挡，并交给 Runtime 验证。困难姿态的面积求解每帧最多迭代 1,536 次，因此短动作也可能耗时数分钟。

本轮优化：

- 只更新含可移动顶点的三角形和边。固定区域仍参与所有收敛与验收检查。
- 骨骼采样直接读取位置、缩放、剪切轨道，避免每次重建整条临时向量轨道。
- 网格采样向调用者返回同一次计算的骨骼变换，修正和插值检查复用它，避免重复计算。
- 自动 QA 时间点若与原始关键帧在 Runtime float32 精度下重合，使用原始时间点。原始关键帧不删除；真正不同的事件冲突在昂贵修正前报错。
- 修正网格和图层烘焙使用同样的采样规则，避免后续再次写出重复时间键。
- Windows 短暂占用进度文件时重试更新，仍被占用则跳过该次通知，不终止已经进行的计算。

真实妖梦困难姿态对照：233 个顶点、84 个可移动顶点、360 个三角形中 154 个需要更新，单次求解从 0.674 秒降至 0.336 秒，约 2 倍。输出坐标和求解记录完全一致，12 组扰动对照一致。这不是完整构建加速倍数。

骨骼采样专项基准使用妖梦实际骨架和合成的 225 帧位移轨道，0.302 秒降至 0.042 秒，结果完全一致。该数字仅代表采样部分。

复现困难姿态基准可使用 `tools/benchmark_active_area_projection.py`，显式传入旧代码版本、冻结请求和独立输出目录。参考报告位于工作区 `tmp/motion-speed-active-v2/report.json`。
