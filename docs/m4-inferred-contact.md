# 无标签动作的接触候选

## 联合根骨与仿射腿链实验

后续 v2 增加相邻支撑采样的关节修正速度限制（180°/s），独立于原动画角速度。SLSQP 参数投影回根骨位移/速度限制后重新计算真实仿射 FK，不用优化器成功标志代替门禁。v1 无旋转速度选项保留。

`support_timeline.py` 为新接触从当前修正姿态记录锚点，保留已有支撑；离地的腿与无支撑根骨通过 0.25 秒释放回原动画。所有原骨骼关键时刻保留，修改仅限根骨平移与四根腿骨旋转。任何无解时刻停止，不导出部分成功的动画；时间轴结果仍需独立密集支点和网格检查。

Alice 侧面行走的三个源稳定区间已通过 764 个密集支点采样、所有附件网格检查及 764 帧官方 Runtime。最大踝部位移 3.332 px（上限 3.531 px），根骨修正速度 655.723 px/s，关节修正速度 179.998°/s；Runtime 最大顶点误差约 0.0000803 px。最终代码重算与捕获文档完全一致。最初重复加密至 1,476 帧的捕获触及 64 MiB 参考限制，保留失败产物；重试使用已完成 QA 的 764 个时刻，没有放宽资源或数值门槛。

此结果尚未默认采用：未覆盖不稳定源接触区间、鞋底碰撞、动态遮挡、人工视觉和三角色通用性。它与上一版固定锚点实验不同，不能将两个位移数直接解释为同一锚点误差改善。精确身份见 [因果联合支撑结果](benchmark/m4-causal-joint-support-v1.json)。下一步将源稳定区间筛选、密集 QA 与此时间轴构建整理为工作台可回退的版本化策略。

`joint_support_solver.py` 在同一时刻同时求根骨平移与最多两条腿链旋转，使用实际非均匀缩放和父级仿射变换。限制保持根骨 15% 参考腿长、关节修正 30°、支点残差 1% 腿长；连续调用可约束根骨速度不超过每秒两倍参考腿长。SciPy SLSQP 的返回成功不作验收依据，独立检查有限值、限制及实际端点残差；搜索失败也不声称数学不可行。

复现：`python tools/diagnose_joint_support.py ../tmp/m4-motion-center/affine-leg/evidence.json ../tmp/m4-motion-center/affine-leg/joint-root-speed.json`。命令重新核对不可变动作、源支撑证据和原先固定锚点，仅处理三个合格区间；任一时刻无解立即停止，不能跳过失败帧拼接结果。

真实 Alice 侧面行走的 356 个独立时刻（369 个接触记录）均找到端点解，覆盖旧固定根骨方式的 40 个未解记录。根骨峰值速度 706.275 px/s 低于 706.281 px/s 上限；但腿骨修正峰值角速度达到 6,871°/s，出现在 2.599609–2.6 秒，尚不能采用。下一步是关节时间连续性、进入/释放过渡、密集网格及官方 Runtime 验证。没有改动正式动画、权重或原始源标签。摘要见 [联合求解记录](benchmark/m4-joint-support-v1.json)。

`motion2d/contact_candidate.py` 的 `bvh-low-stationary-ankle-v1` 从已验证 BVH 世界坐标生成独立假设，不写回源 MotionIR，不覆盖原有接触配置，也不直接触发角色根骨修正。

使用映射声明的双侧小腿目标关节作为踝部代理，沿声明的 screen_y 取全部踝部高度的第 5 百分位。该数值是观察到的低位代理，不是地面测量。高度带为参考腿长的 2.5%，三维速度上限为每秒参考腿长的 8%；至少持续 0.12 秒且不少于三帧，不补齐间隙。检测复用已有 BVH 接触模块，保留半开区间与来源、原映射、派生映射身份。

缺少双侧映射、帧数不足或循环边界未经处理时返回不可用。静止的悬空姿势与真实支撑无法仅凭这些信息区分；跑步机、移动平台也不能按世界静止规则推断。此阶段不把候选计入接触验收通过率。

运行方式（仓库目录，PYTHONPATH=src）：

```powershell
python tools/diagnose_motion_contact.py motion-<id> ../tmp/contact/report.json
```

下一步需要判断漂移来自源动作支撑假设还是重定向，再接入相应修正；不以几何通过覆盖接触异常。原有 Kimodo 标签、固定 24 项历史基线和已经验收的角色均未改动。

## 静止双脚候选验证

源待机双脚相对初始位置的三维位移分别为参考腿长的 0.723% / 0.158%，目标却出现 26.173 px 位移。共享根骨修正剩余 4.350 px 双脚冲突；受限旋转实验也未通过，未保留为生产代码。

新增独立 `stationary_ankle_candidate.build`：仅接受全片双脚区间，先生成有界根骨修正，再在父骨仿射坐标中施加小幅踝端平移。根骨位移上限保持腿长 15%，端点上限 2%，两者修正速度上限均为每秒腿长 2 倍；最终漂移门槛仍为腿长 1%。保留骨架、权重、纹理及足部旋转/缩放，只改变动画平移。短暂、交替或单脚支撑不被静默扩展。

Alice 独立候选最大踝端平移 4.350 px，漂移降至 0.001141 px；1,108 帧、26 附件的几何与官方 Runtime 捕获通过。12 项仿射、尺度、冲突拒绝及工程质量测试通过。见 [精确候选证据](benchmark/m4-stationary-ankle-v1.json)。

独立实验当时未接入默认工作台采用，也未证明鞋底接地、遮挡或人工视觉通过；之后的自动策略另行记录如下。

## 默认自动策略

自动策略最初使用 `external-stationary-contact-auto-v1`，新任务现使用下述 v2 向上轴修复。在没有源接触标签且未裁剪时，只有推断区间覆盖全片双脚、两只源踝的三维位移均不超过源腿长 1%，才尝试上述有界修正。对目标密集采样的接触与几何均通过后，才在新候选中自动采用；缓慢滑行、单脚/交替支撑、修正超限或新增网格异常时保留原动画与异常。现有源标签仍优先走原修正链。

策略身份保存在任务请求与产物中；历史 measurement-v1 请求保持原行为。关闭“尝试小幅支撑修正”即可重建未修正版。角色骨架、权重、贴图和历史候选保持不变。这里保持的是源踝部近静止位置，不把推断标记写入原始 MotionIR，也不宣称真实地面或鞋底接触。

20 项自动策略、仿射、回退、目标任务及工程质量测试通过；浏览器验证自动采用报告和 Alice 三秒播放位置，无脚本错误。固定三角色新待机对照见 [自动采用证据](benchmark/m4-stationary-auto-cohort-v1.json)，它不替换原 24 项正面基线或代表其余七类动作通过。

## 源向上轴修复 v2

发现并修复旧推断错误：动作中心的屏幕竖轴为 `-Y`，但 Mixamo 来源约定向上为 `+Y`。直接取屏幕坐标的低分位会选到较高的脚部位置。新 `bvh-declared-up-stationary-ankle-v2` 先沿明确的源向上轴计算低位分位，再转换回映射的竖轴；不从屏幕符号猜测重力。竖轴与源向上轴不共线时拒绝推断。

工作台新目标请求使用 `external-stationary-contact-auto-v2`；旧 measurement-v1 / auto-v1 请求仍能按原算法重放，原 MotionIR 与历史证据不覆盖。源动作诊断页面显示当前 v2 结果。

对同一七类固定来源重测，区间数为：待机 2、行走 4、抬臂 6、转体 2、下蹲 2、拳击 5、伸手 2。待机区间与旧版完全相同；不能据此推定其他动作接触正确。24 项测试通过，浏览器验证行走四段时间带及 0.367 秒定位，无脚本错误。

同源侧面行走重新构建 Alice 后，377 帧几何/Runtime 通过，但推断区间内踝部位移仍为 79.688 px。候选保持异常，未将全片双脚修正强套到交替支撑。精确来源、区间及任务证据见 [v2 对照](benchmark/m4-contact-up-v2.json)。后续仍需处理支撑切换、释放过渡及动态遮挡。

## 支撑切换与释放实验

`contact_phase_candidate` 在进入新支撑时锁定当前已修正的位置；旧支撑结束后使用连续释放，在释放途中进入新支撑时避免重复混合旧约束。同脚重叠区间拒绝，双脚冲突仍由漂移门槛检查。该模块只生成诊断候选，不接入默认采用。

在上述同源侧面行走产物上，漂移从 79.688 px 降到 11.690 px，仍超过 3.531 px；最大根骨修正 79.688 px、修正速度 1474.541 px/s，均超过原有比例限制。候选拒绝，未改写工作台产物，也没有为该失败候选运行几何或官方 Runtime 验证。不能借用输入产物的 377 帧检查作为新修正的通过证据。

12 项连续切换、释放接管、速度限制、双脚冲突、既有接触及工程质量测试通过。精确输入身份和逐区间结果见 [支撑切换实验](benchmark/m4-contact-phase-v1.json)。可通过以下命令重放，输出仅为诊断报告：

## 逐区间源稳定性

动作中心的源动作预览现在额外检查每个推断区间内的三维累计踝部位移。速度低不等于位置固定：`source-contact-phase-stationarity-v1` 使用半开区间的第一个源样本作为锚点，累计位移超过源腿长 1% 或不足两个样本时，不将该区间视为可锁定证据。检查核对源 BVH 与映射身份，不裁短区间来提高通过率，不删除推断标记，不修改 MotionIR。

七类固定来源的 23 段中，21 段满足此限制：待机 2/2、行走 3/4、抬臂 6/6、转体 2/2、下蹲 2/2、拳击 5/5、伸手 1/2。行走左脚 0.367–0.733 秒累计位移为腿长 1.96%，不能仅因速度较低而锁脚。见 [逐区间来源证据](benchmark/m4-phase-support-v1.json)。这是源踝稳定性检查，不代表地面接触、目标可达性或动作最终通过。

入口仍为动作中心 → 查看源动作 → 支撑区间与接触证据。橙色时间带明确显示“不宜锁脚”，每段显示累计位移比例并可点击定位。Kimodo 已编译的源接触标签继续优先，不经过此 BVH 推断分类。已有目标任务与自动采用策略不变。

20 项模块、接触接口、旧推断和工程质量测试通过。真实浏览器验证行走 3/4 稳定性说明、橙色异常区间和 0.367 秒时间定位，无脚本错误。下一步局部修正必须先消费这类源证据，再验证目标可达性与变形。

## 有界仿射腿链求解

`affine_leg_ik.solve` 在真实父骨仿射坐标中求解两根腿骨的旋转，保留动画中的非均匀缩放、局部偏移和长度。下段在 ±30° 内搜索，上段旋转由端点方向确定并同样限幅；未找到解不等于证明无解。另用三角不等式提供保守外部可达范围，只有超过该上界才报告端点过远。

`tools/diagnose_leg_contact.py` 核对源包和推断身份，只在源累计位移满足 1% 限制的区间试算，并对比原根骨与最多腿长 15% 的根骨修正。释放时间在此独立实验中为 0.25 秒，根骨修正速度仍检查每秒腿长 2 倍。没有替换工作台默认策略。

同一 Alice 侧面行走中，369 个稳定源区间内的目标样本，原根骨下 266 个未求解，加入有界根骨修正后为 40 个：右脚首段 28 个超过保守腿链可达上界，右脚短段 12 个没有找到限角解；左脚长支撑 179 个均找到端点解。根骨修正速度通过限制。该结果仅为逐帧端点实验，尚无时间连续性、网格变形或 Runtime 通过证据，候选不采用。精确时间点见 [仿射腿链记录](benchmark/m4-affine-leg-v1.json)。

17 项仿射端点恢复、不可达、源区间、支撑切换及工程质量测试通过。此例说明部分动作需要调整目标适配或明确支持范围，不能只通过持续放宽锁脚限制解决；M4 后续继续处理动态遮挡和整体支持范围。
