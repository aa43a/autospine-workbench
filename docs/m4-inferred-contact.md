# 无标签动作的接触候选

`motion2d/contact_candidate.py` 的 `bvh-low-stationary-ankle-v1` 从已验证 BVH 世界坐标生成独立假设，不写回源 MotionIR，不覆盖原有接触配置，也不直接触发角色根骨修正。

使用映射声明的双侧小腿目标关节作为踝部代理，沿声明的 screen_y 取全部踝部高度的第 5 百分位。该数值是观察到的低位代理，不是地面测量。高度带为参考腿长的 2.5%，三维速度上限为每秒参考腿长的 8%；至少持续 0.12 秒且不少于三帧，不补齐间隙。检测复用已有 BVH 接触模块，保留半开区间与来源、原映射、派生映射身份。

缺少双侧映射、帧数不足或循环边界未经处理时返回不可用。静止的悬空姿势与真实支撑无法仅凭这些信息区分；跑步机、移动平台也不能按世界静止规则推断。此阶段不把候选计入接触验收通过率。

运行方式（仓库目录，PYTHONPATH=src）：

```powershell
python tools/diagnose_motion_contact.py motion-<id> ../tmp/contact/report.json
```

工作台入口：动作中心选择“查看源动作”，在同页“支撑区间与接触证据”中查看双脚时间带，点击时间带或区间按钮定位源时间轴。`GET /api/motions/{id}/contacts` 每次核对原始文件与精确 MotionIR 包，源标记优先于推断；切换动作会清空旧区间并丢弃迟到响应。接口只读，不执行采用或锁脚。

真实浏览器验证：呼吸待机双脚区间可定位，切换行走后旧区间清空，显示证据不足；Kimodo 挥手保留两条源标记，页面无脚本错误。相关 14 项单元、接口与工程质量测试通过。

新目标任务已启用 `external-inferred-contact-measurement-v1`：源 MotionIR 没有接触标记时，在独立推断窗口内测量目标踝部漂移，生成可定位的接触异常。裁剪区间先求交集再平移；原 MotionIR 不增加标记，历史请求缺少此 profile 时仍保持旧行为。现有源标签优先，仍使用原有有界修正。推断窗口暂不授权锁脚。

真实 Alice 呼吸待机新任务通过 554 帧官方 Runtime 与几何检查，但推断窗口内最大踝部位移 26.173 px，超过 3.531 px 门槛，因此保持异常候选。浏览器报告展示双脚记录并提供 3 秒异常定位链接。完整任务身份见 [目标接触记录](benchmark/m4-inferred-target-contact-v1.json)。16 项接触、目标任务与工程质量测试通过。

下一步需要判断漂移来自源动作支撑假设还是重定向，再接入相应修正；不以几何通过覆盖接触异常。原有 Kimodo 标签、固定 24 项历史基线和已经验收的角色均未改动。

## 静止双脚候选验证

源待机双脚相对初始位置的三维位移分别为参考腿长的 0.723% / 0.158%，目标却出现 26.173 px 位移。共享根骨修正剩余 4.350 px 双脚冲突；受限旋转实验也未通过，未保留为生产代码。

新增独立 `stationary_ankle_candidate.build`：仅接受全片双脚区间，先生成有界根骨修正，再在父骨仿射坐标中施加小幅踝端平移。根骨位移上限保持腿长 15%，端点上限 2%，两者修正速度上限均为每秒腿长 2 倍；最终漂移门槛仍为腿长 1%。保留骨架、权重、纹理及足部旋转/缩放，只改变动画平移。短暂、交替或单脚支撑不被静默扩展。

Alice 独立候选最大踝端平移 4.350 px，漂移降至 0.001141 px；1,108 帧、26 附件的几何与官方 Runtime 捕获通过。12 项仿射、尺度、冲突拒绝及工程质量测试通过。见 [精确候选证据](benchmark/m4-stationary-ankle-v1.json)。

独立实验当时未接入默认工作台采用，也未证明鞋底接地、遮挡或人工视觉通过；之后的自动策略另行记录如下。

## 默认自动策略

自动策略最初使用 `external-stationary-contact-auto-v1`，新任务现使用下述 v2 向上轴修复。在没有源接触标签且未裁剪时，只有推断区间覆盖全片双脚、两只源踝的三维位移均不超过源腿长 1%，才尝试上述有界修正。对目标密集采样的接触与几何均通过后，才在新候选中自动采用；缓慢滑行、单脚/交替支撑、修正超限或新增网格异常时保留原动画与异常。现有源标签仍优先走原修正链。

策略身份保存在任务请求与产物中；历史 measurement-v1 请求保持原行为。关闭“尝试小幅支撑修正”即可重建未修正版。角色骨架、权重、贴图和历史候选保持不变。这里保持的是源踝部近静止位置，不把推断标记写入原始 MotionIR，也不宣称真实地面或鞋底接触。

20 项自动策略、仿射、回退、目标任务及工程质量测试通过；浏览器验证自动采用报告和 Alice 三秒播放位置，无脚本错误。固定三角色新待机对照见 [自动采用证据](benchmark/m4-stationary-auto-cohort-v1.json)，它不替换原 24 项正面基线或代表其余七类动作通过。

## 源向上轴修复 v2

发现并修复旧推断错误：动作中心的屏幕竖轴为 `-Y`，但 Mixamo 来源约定向上为 `+Y`。直接取屏幕坐标的低分位会选到较高的脚部位置。新 `bvh-declared-up-stationary-ankle-v2` 先沿明确的源向上轴计算低位分位，再转换回映射的竖轴；不从屏幕符号猜测重力。竖轴与源向上轴不共线时拒绝推断。

工作台新目标请求使用 `external-stationary-contact-auto-v2`；旧 measurement-v1 / auto-v1 请求仍能按原算法重放，原 MotionIR 与历史证据不覆盖。源动作诊断页面显示当前 v2 结果。

对同一七类固定来源重测，区间数为：待机 2、行走 4、抬臂 6、转体 2、下蹲 2、拳击 5、伸手 2。待机区间与旧版完全相同；不能据此推定其他动作接触正确。24 项测试通过，浏览器验证行走四段时间带及 0.367 秒定位，无脚本错误。

同源侧面行走重新构建 Alice 后，377 帧几何/Runtime 通过，但推断区间内踝部位移仍为 79.688 px。候选保持异常，未将全片双脚修正强套到交替支撑。精确来源、区间及任务证据见 [v2 对照](benchmark/m4-contact-up-v2.json)。后续仍需处理支撑切换、释放过渡及动态遮挡。

## 支撑切换与释放实验

`contact_phase_candidate` 在进入新支撑时锁定当前已修正的位置；旧支撑结束后使用连续释放，在释放途中进入新支撑时避免重复混合旧约束。同脚重叠区间拒绝，双脚冲突仍由漂移门槛检查。该模块只生成诊断候选，不接入默认采用。

在上述同源侧面行走产物上，漂移从 79.688 px 降到 11.690 px，仍超过 3.531 px；最大根骨修正 79.688 px、修正速度 1474.541 px/s，均超过原有比例限制。候选拒绝，未改写工作台产物，也没有为该失败候选运行几何或官方 Runtime 验证。不能借用输入产物的 377 帧检查作为新修正的通过证据。

12 项连续切换、释放接管、速度限制、双脚冲突、既有接触及工程质量测试通过。精确输入身份和逐区间结果见 [支撑切换实验](benchmark/m4-contact-phase-v1.json)。可通过以下命令重放，输出仅为诊断报告：

```powershell
$env:PYTHONPATH='src'
python tools/diagnose_contact_phase.py d75ec56c500c42ddb9d88aad9c8742f2fd938fb309b5e41c32b21d274507e3df ../tmp/m4-motion-center/contact-phase/evidence.json
```

下一步需结合源动作支撑真实性检查与局部腿部约束，避免单靠整体根骨位移消除行走漂移；位移、速度及漂移门槛保持不变。
