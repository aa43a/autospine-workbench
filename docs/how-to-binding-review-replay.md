# 沿用未变化区域的绑定确认

整角色候选的“确认已有区域绑定”会显示“沿用未变化区域的原确认”。它只减少重复的绑定复核，
整角色的 setup、连接、动作和绘制顺序视觉验收仍针对当前包单独执行。

第一种支持的变化：在动作、纹理修复、裙装生成后，排除用户已确认的静态残余。
系统逐项验证：

- 唯一前序包及其原人工绑定确认，且原 Runtime 和几何检查通过；
- 新旧来源相同，所有 PNG、Atlas、剩余骨骼、附件与动画相同；
- 所有动作帧的剩余顶点完全一致，目标层的覆盖账本也完全一致；
- 新包已完成独立 Runtime 与几何检查。

条件不满足时保留待复核，不挑选另一个“相近”来源。前序确认被撤销后，下次读取就停止沿用。
页面可对每层点击“撤销区域确认”；这只否定当前候选的沿用，不改写前序人工记录。
重新显式确认则记录本次操作。新旧客户端的原 v1 请求与历史保持兼容；需要沿用撤销的记录使用 v2。

沿用证据为 `character-binding-replay-v1`，按摘要存入独立 `binding-replay-evidence`，可以精确回读。
它标记 `verified_scope_replay`、`new_human_confirmation: false`，不伪造人工操作，
也不计作新语义推断的自动采用准确率。v2 只保存本次显式确认/撤销及当时沿用证据的摘要。

真实验证见 [三层裙装绑定沿用](benchmark/character-binding-replay-v1.json)。

第二种支持的变化：把一个静态源区域替换为独立组件。系统核对保留的 PNG、原 Atlas 内容、
原骨架/动画/附件、插入位置及剩余顶点，逐层比较未修改账本。只沿用未参与替换的图层确认。
对应证据是 `character-binding-replay/v2`，它可以引用原人工记录，或引用经过一次最终排除核验的 v1 证据。
不支持任意转换链递归继承。中间候选的撤销与最初人工记录的撤销都会在再次读取时生效。
这一机制不会新增人工确认、自动确认新组件或复用整角色视觉验收。

小恶魔工作台的两层裙装已通过这一证明恢复原确认，见
[真实工作台复用证据](benchmark/xiaoemo-component-binding-replay-v1.json)。

## 检查实际绑定

“确认已有区域绑定”逐区域列出真实驱动骨骼，并可展开顶点数量和非零权重范围。数据直接解析当前包，拒绝非有限数、无效骨骼索引、重复影响、错误权重和及顶点数量不匹配。它只描述已经生成的结果，不证明语义正确，也不会自行确认。

## 保存残余排除后更换重建动作

如果当前只保存了最终残余排除，工作台“整角色动作”仍可选择重新生成的动作方案，再点击构建。裙装、纹理修复等原选项保持固定。构建会重新核对排除区域的来源、内容、几何和逐帧位置；完全一致才继续应用原排除，变化则停止并保留原确认记录。

已有同层部件映射、拆分后排除或绘制顺序确认时，动作仍被原方案约束。旧后端也维持原锁定行为，避免界面放开后缺少对应校验。残余排除的校验本身不等于骨骼绑定或视觉验收。

## 重建后的未变化绑定

对于已重新校验残余排除的候选，绑定复核现在另行核对唯一的原人工确认、新旧骨架、逐层账本、附件、纹理及全部逐帧顶点。只有完全未变化的有效层才沿用原确认。证据使用 `character-binding-replay/v4`；不递归寻找转换链，也不沿用整角色视觉验收。

每次读取都重新检查原确认，撤销后停止沿用；当前候选也可单独撤销。范围核验期间发生原确认变化时，本次不产生沿用证明。同一次请求共用已验证数据，并在读完后再次检查来源，无跨请求信任缓存。

芙兰当前候选已恢复五层确认，见 [重建绑定验证](benchmark/flandre-rebuilt-binding-replay-v1.json)。该结果不构成新的自动语义判断或准确率样本。
