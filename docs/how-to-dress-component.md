# 从混合衣层生成连衣裙组件候选

当 topwear 同时包含连衣裙与翼片、挂饰时，先用原父骨骼拆出独立连通域，保留每个非零 RGBA 像素、原绘制顺序与原动画。拆分不授予绑定确认。

运行 `tools/build-dress-component.py --state-root workspace --character <候选地址> --slot <源区域> --component <连通域编号>`。
入口消费现有工作台整角色包，并将分区和变形结果分别发布到原内容寻址仓库；输出仍是完整 Spine 4.3.26 候选。

选中的组件必须属于 topwear/topwear-front、只有一个主要连通域、胸部锚点有可见像素支持且延伸到髋部以下。腰线在胸部至平均髋部高度的 20%–60% 范围内按连续三行宽度中位数提出；这不是已确认的解剖腰线。上身随候选 chest，裙摆使用三条双骨辅助链，继续复用既有网格和动作 QA。

其他组件保持 static_reference，不自动授予距离最近骨骼。输出报告使用 `isolated-dress-chest-skirt-v1`，含腰线、支持证据与待复核状态；原普通裙装路径及历史地址不变。

工作台的整角色构建区可勾选“生成裙装可变形候选”，处理方式选择“连衣裙组件（自动寻找）”，再构建整角色候选。系统检查未处理的 topwear/topwear-front，逐层选择唯一满足胸部覆盖与跨髋条件的组件。找不到或出现多个符合项时保留该层并列出异常；不改写已确认的刚性层。

前后衣层先分别分区，再一次性编译选中的组件，避免后一次编译覆盖前一次裙装报告。分区证据和完整结果独立存储，构建配方记录处理方式；原有独立裙层与历史方案仍可重建。取消裙装选项并重建可恢复基础结果；若已有后续精确复核决定，需先撤销对应决定再改变配方。

既有低透明度残余选项在此方案中先于分区执行；选择保留时不执行。其他组件仍是待处理静态区域。候选继续进入统一图层账本、时间轴及官方 Runtime 检查，腰线和前后衣片遮挡仍需阶段验收，不计作已完成绑定。
