# 查看实际像素分区候选

在仓库目录运行，不需要填写 SHA：

```powershell
$env:PYTHONPATH='src'
python tools/build-component-partitions.py --output ../tmp/r3a-component-partitions lumia huiye uuz yaomeng
```

项目需要已有当前全角色规划和有效动画来源。工具读取完整来源链，为加权 Mesh、分区 Mesh、语义异常三类图层生成候选。
打开输出目录的 `index.html`，选择角色。每层显示原纹理和实际像素分区，可关闭叠加、悬停查看区域及打开候选 JSON。

算法按 alpha≥8 的四连通区域记录 layer-local 半开游程 `[y,x_start,x_end]`，bbox 保持原画布坐标。
所有 0<alpha<8 像素独立保留，不根据距离分配给骨骼；透明像素不属于可见覆盖集合，原纹理字节始终保留。
各区域 owner 为 null，bone_ids 为空。连通域不等于左右归属、服装语义或可安全变形的 Mesh。

候选按内容地址保存在 `project-component-partitions/candidates-v1` 报告集合中，引用完整来源地址与原规划 SHA。
读取后用原图重新计算并验证结果。重复运行复用相同内容地址，不修改已保存绑定、语义或纹理。
报告是独立检查入口；本切片尚未把分区加入主工作台的正式绑定保存或 Spine 编译。

这些结果不表示残余像素有错，更不构成 Mesh、接缝或官方 Runtime 验收。

## 区域归属草稿

骨骼画布模式：淡色完整角色提供位置参照，当前图层区域与全部骨骼按原画布坐标叠加。
点击「① 选区域」，再点击像素区域；页面自动进入「② 选骨骼」。点击骨骼添加/取消，高亮显示当前选择，最多 4 根。
在右侧选择语义与侧别，点击「将当前选择写入草稿」才进入可下载记录；切换区域会重新载入该区域已有草稿，请先写入当前选择。
低 alpha 残余禁止骨骼点选绑定。列表选择骨骼作为重叠骨骼难以点选时的备用入口。
7 项 Python/质量检查及 464 项 Web 测试通过；已验证全画布偏移、骨骼坐标和点选限制。本轮未完成浏览器页面截图验证。

便捷模式：顶部选择图层；左侧点击区域，右侧查看建议，再点「使用当前区域建议」。
「一键预填可靠建议」只填写 pending 区域，不覆盖已有草稿；「下一个未处理区域」跳过锁定的低 alpha 残余。
手动语义和骨骼集合收在「手动调整语义与骨骼」中。可继续使用载入、撤销与下载；关闭页面前仍需下载保存。

自动建议使用独立 `semantic-component-bone-samples-v1` profile：明确语义或限定名称别名、同侧且语义兼容的现有骨骼选项、区域内每骨 21 个采样点、平均覆盖至少 35%、最高与次高差至少 15%。
左右依赖当前骨架及明确名称侧别，不按画布左右猜测。未知物件、裙装、低 alpha 残余及冲突方案不预填。
建议随精确来源独立封存，可追溯候选集合、骨架和绑定来源；不会修改像素分区或产生人工批准记录。
四角色分别获得 4、2、4、4 个建议区域，共 14/85；这是建议覆盖数，不是正确率或通过验收数。

新版报告支持点击区域或通过下拉框选择，填写语义、角色侧别及当前骨架中的 1–4 根骨骼。
点击「将当前选择写入草稿」后，可下载全部区域草稿；没有点击写入的表单选择不会导出。
「保留未归属」清除当前区域填写，「撤销至上次载入草稿」恢复最近一次载入内容（初始为空草稿）。
关闭页面前请下载草稿；页面不自动保存。载入 JSON 时会核对项目、输入、规划、全部候选及区域集合。
黄色低 alpha 残余本版不能指定归属。骨骼集合只记录复核意图，不表示已有权重或合法连续骨链。

### 区域三角网格诊断

在上述命令增加 `--mesh`，生成 `mesh.html`。它复核原始像素分区，再逐区域隔离 alpha、
复用已有 alpha-grid 三角化和 joint-plane 三骨权重（与前一步距离权重采样属于不同 profile）。
足部使用单骨刚性权重。诊断 alpha 不包含其他区域或低 alpha 残余，原始 PNG 不变；
不能直接把这些网格配上未隔离的共享纹理导出，否则可能显示相邻区域像素。

每条三骨链逐骨检查 0、±15、±30、±60、±90°，单骨同样检查九个角度。
setup 误差≤1e-7 px、权重和误差≤1e-9、翻转为零、面积比在 [0.5,2]、边长倍率≤2，
并要求诊断 alpha 全覆盖。任意姿态超限保持 blocked；全部通过也仅为待复核候选。
结果由 `component-isolated-grid-joint-plane-v1` 记录，复用独立 16 MiB Mesh store，读回重算验证。
报告可切换姿态，红色显示翻转、黄色显示面积超限；它是 CPU 线框诊断，不是官方 Runtime。

2026-09-09 用户明确左鞋与右鞋同类后，修订草稿只将左鞋 body.leg 改为 body.foot，
保留 left / foot_l，原下载草稿未覆盖。Lumia 生成 6 个网格，共 1,324 顶点、2,124 三角形。
6 区域 setup 可见像素漏覆盖为 0；双鞋通过数值门槛，双腿/双臂未通过全部弯曲检查。
左腿及双臂在部分 15° 姿态已有面积超限。裙装、未归属区域和 5,407 低 alpha 残余仍保留。
下一步先改善四肢局部权重过渡，再检查跨附件接缝；本次没有接缝或 Runtime 通过证据。
16 项针对性和质量测试、实际报告 Schema 检查通过，未完成浏览器截图验收。

### 局部权重过渡对照

在 `--mesh --draft ...` 命令中增加 `--weight-transition`，生成 `transitions.html`，
可在原网格页和新对照页之间切换。两者使用相同的顶点、三角形、UV 和诊断纹理。
独立 `component-alpha-width-both-joints-v1` profile 测量每个关节附近实际区域的横向 alpha 支撑，
尝试半径倍率 1、2、4；半宽不小于原值，不大于相邻较短骨长的 90%。
只有权重比例变化，local 坐标保持原值；所有逐骨九角度探针重新运行。

试验方案须同时不增加失败姿态数、不增加所有探针翻转总数，至少改善一项，
并且不得使原先通过的姿态新增失败。否则保留原权重。此选择只是实验比较，不写正式绑定。
每个方案的数值指标、支撑测量和参数完整存档，源 Mesh 与骨架内容地址绑定，输出读回重算。

Lumia 对照：右腿失败姿态 10→7，左腿 11→8；右臂失败姿态维持 11，翻转总数 27→21。
左臂减少失败姿态的试验增加了翻转总数，因此保留原结果。四肢仍未通过完整数值门禁；
双鞋、裙装与残余记录保持原状。下一步需要定位剩余问题的三角形和关节，而非放宽门槛。
14 项针对性及质量测试通过；尚未获得接缝或 Runtime 验收。

### 异常三角形局部修正

增加 `--local-correction`（需要 `--mesh --weight-transition --draft ...`）生成 `corrections.html`。
页面提供同一关节角度的「原」与「试验」线框；各卡片标题仍表示源 Mesh 的门禁，
修正后的数值以姿态读数为准。候选依赖精确的权重对照与骨架内容地址，并读回重算验证。

`component-local-area-ring-v1` 只移动异常面积三角形及一圈邻接三角形中的混合权重顶点，
固定迭代 48 次，位移上限为最短骨长的 10%。投影目标面积比 [0.55,1.9]、边长倍率≤1.9；
验收阈值仍为原有 [0.5,2] 和≤2。试验不能新增异常面积三角形、增加翻转或破坏原通过的边长门槛，
没有改善就恢复原姿态。顶点绑定坐标、权重、UV 与三角拓扑不变，输出只包含独立姿态候选。
