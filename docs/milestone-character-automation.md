# 整角色自动化后三个里程碑

基线：627c65d，普通袖受限候选闭环完成。默认 Spine 4.3.26。
顺序执行 C1 → C2 → C3；当前开展 C1，不把局部候选通过计作整角色通过。

## C1 整角色闭环

从工作台生成统一候选。每个源层必须有记录，每个输出区域必须能追溯到源层。
区分加权候选、已复核刚性跟随、静态参考、未处理、显式排除和非可见层；
保留部分区域成功、部分区域失败，不用附件数量代替源层覆盖率。

交付顺序：
1. 独立覆盖账本、精确输入校验、工作台逐层定位及机器报告。
2. 肢体与普通/宽袖候选合并器：匹配源、骨架与动作，拒绝重复消费；不兼容返回原因。
3. 同一预览包的纹理、draw order、setup 重建及 Runtime 验证。
4. 工作台构建、恢复、下载和异常定位闭环。

验收：全部源层及输出区域可追溯；不存在静态参考冒充完成绑定；袖装修正真实进入统一包；
输入变化使依赖结果失效；历史包不改写。人工视觉验收独立记录。

## C2 仅异常复核

先实现简单刚性区域，逐步扩展明确分区；跨部件、遮挡和证据不足保留人工队列。
版本化 policy_auto 决定必须绑定确切候选、来源、阈值与证据，禁止覆盖人工决定。
支持批次预览、撤销、来源变化失效及下游重建。

验收：人工与自动来源可区分；撤销可重放；没有静默放宽阈值；
抽查精度目标 98% 仅在独立人工参考齐备后计算，未测量不得报告达标。

## C3 固定角色集、多动作验收

先选择三种不同结构的角色完成 C1/C2，再扩展既有首批十角色清单。
开发/可见/holdout 分组保持原划分；不得将调参样本称作独立测试。
目标动作 idle、wave、walk；逐角色声明支持范围和超范围阻塞。

记录实际端到端完成率、人工结构修改、复核耗时、自动采用抽查与 Runtime 失败。
耗时从真实操作事件计算，历史数据不足标为不可用；不能用阶段成功率代替角色成功率。
三角色验收通过后才进入十角色门槛校准，不因局部报告好看调整固定策略。

## 工程边界

复用既有编译器、内容寻址读写与隔离 Runtime；新代码按分析、存储、接口、视图分模块。
新文件 300 行预警、400 行上限；不增加旧 P10 纵向证据阶段。
PNG 自动分层、表情/次级运动和 Blender 保留后续计划，不插入本轮关键路径。

## C1 第二个交付：袖装与整角色合并核心

`tools/build-character-sleeves.py PROJECT --sleeve-job JOB` 读取当前来源和明确选择的袖装任务。
采用任务原有下载校验、撤销检查、源版本检查和独立内容寻址库存。
合并模块放在 `targets/character43`，不扩大历史 `targets/spine43` 身份扫描范围。

显式匹配骨架 setup；新增 helper 骨骼重排加权顶点索引；动作同名且共享骨通道一致才组合。
保留原 deform，移除不兼容的旧预览动作。原袖层由分区替代，RGBA 子集逐像素检查，
剩余像素独立静态保留；重复归属、非源像素、未知图层和动作冲突拒绝合并。
全源层账本随新候选封存，不将旧 QA 或局部 Runtime 报告提升成整角色通过。
