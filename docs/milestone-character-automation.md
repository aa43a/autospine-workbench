## C1 整角色闭环

工作台整角色区提供“当前还差什么”：独立显示绑定待办、采样网格、Runtime 报告和四项视觉验收。点击“查看并记录视觉复核”读取当前候选记录并展开表单；保存后概览同步更新。未读取、尚未复核、需要修改均不会被数值通过覆盖。未保存校正时提示候选不能代表最新修改。

若当前来源只有一个包含 idle、wave-left、walk 的有效动作组合，工作台构建默认选择该组合。多个完整组合、过期来源或动作缺项时不猜选；用户手动选择“保留原有动作”会在同一项目刷新期间保持。此默认只选择预览输入，不采用绑定或视觉结论；服务继续核验动作来源。

视觉复核表单可显式开始/暂停计时，查看 Runtime 时可继续计时，离开复核时需手动暂停。保存复核会暂停并保存累计秒数，重新读取后可继续。未启动计时的历史记录保持未测量；这记录操作员划定的会话时间，不推断注意力、空闲时间或全部项目人工耗时。候选切换清空未保存计时，计时与复核应一同保存。

评估器每角色单列 `visual_review_session_minutes`；总人工耗时仍为 null，直到覆盖其他复核阶段。重复保存不累加重复会话，旧客户端保存会保留已有计时，计时回退及非有限/越界值被拒绝。

从工作台生成统一候选。每个源层必须有记录，每个输出区域必须能追溯到源层。
区分加权候选、已复核刚性跟随、静态参考、未处理、显式排除和非可见层；
保留部分区域成功、部分区域失败，不用附件数量代替源层覆盖率。

交付顺序：
1. 独立覆盖账本、精确输入校验、工作台逐层定位及机器报告。
2. 肢体与普通/宽袖候选合并器：匹配源、骨架与动作，拒绝重复消费；不兼容返回原因。
3. 同一预览包的纹理、draw order、setup 重建及 Runtime 验证。
4. 工作台构建、恢复、下载和异常定位闭环。

验收：全部源层及输出区域可追溯；不存在静态参考冒充完成绑定；袖装修正真实进入统一包；
输入变化使依赖结果失效；历史包不改写。人工视觉验收独立记录。

## 自动采用基础：紧凑鞋类证据与可撤销决定

新增 `compact-foot-binding-v1` 试验策略与 CLI `tools/simple-binding-policy.py PROJECT`。
默认仅检查；`--action apply` 采用通过全部检查的候选，返回决定摘要；
`--action undo --decision SHA` 撤销该次采用。还未接入工作台按钮。
检查包含源像素摘要、单连通区、踝点可见接触、部件范围、小腿跨度、左右距离差和共享目标冲突。
未支持部件、已有记录/备注、不满足几何条件的区域继续复核。
这是有明确条件的工程策略，准确率仍为unmeasured，不能声称已达到98%抽查准确率。

决定单独保存 `policy_auto`、原/新草稿、原/新注册身份和完整证据，不修改历史合同。
先写证据、再以注册追加作为生效点；未提交证据不能撤销。撤销要求当前仍是该次结果，
后续人工编辑即使只改备注，也禁止被旧撤销覆盖。不会产生生产授权。
