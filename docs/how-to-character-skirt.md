# 整角色裙装候选

工作台的“动画预览 → 整角色候选”增加“生成裙装可变形候选”选项，默认关闭。
保存当前校正后，勾选该项并构建；进度会显示裙装生成、官方 Runtime 和待复核状态。
完成后原有 Runtime 按钮变为“查看裙装与整角色时间轴”，不另增侧栏入口。
时间轴播放官方已捕获帧，可切换动作、拖动查看和暂停；它不插值生成未捕获的画面。

关闭选项并重新构建可恢复原输出。原始 PNG、Atlas、绘制顺序、既有骨骼和人工决定均保留。
新包有独立内容地址，不修改旧包或复用旧包的视觉验收。

## 当前候选范围

仅处理仍为静态参考的 `bottomwear / bottomwear-front`。已完成刚性或其他处理的图层不覆盖。
需要已复核上衣与可用骨架，并检查裙装与上衣的实际透明轮廓重叠。
算法提出上部持续重叠带作为腰部候选；骨盆/髋部只提供范围参考，不把骨骼名称当作真实腰线。
没有可观测接触会返回明确原因。
单层接触或网格分析失败时，该层保留原图和逐层原因，其他可处理裙装继续生成；
不会为了让整个任务通过而丢掉失败层，也不会因一个异常层取消其他候选。

每层保留独立纹理，生成三条双骨辅助链。腰部及以上顶点随 pelvis，下面按纵向平滑过渡，
横向最多混合相邻两链；每顶点最多四骨、权重归一化，不接入手骨或腿骨。
网格覆盖全部有 alpha 的像素；透明洞仍由原纹理保留，连通域和根部缺证据继续显示。

黄色虚线表示腰部候选，蓝线为辅助骨链。黄色根点具有上衣 alpha 重叠支持，红点缺少这种支持。
骨链叠加只在 Setup 帧显示，不能把 Setup 位置叠到其他动作帧。

已有动画追加小幅确定性测试：idle 为 2°、其余动作 4°、下段幅度减半。
这是可变形候选及检查动作，尚不是衣料物理，也没有完成腿部碰撞、动态接触或遮挡求解。
腰部位置、根点和裙摆效果都未自动采用；它们继续进入逐层待办。

## 本次真实验证

红美铃两层、小恶魔两层、辉夜一层，共五层使用同一策略，无角色名专用算法。
原骨架、未选中附件动作、纹理和顺序的保存检查通过；Setup 几何误差小于 1e-6 px。
官方 spine-webgl 4.3.13 捕获 Spine 4.3.26 候选：1,028 / 1,675 / 2,062 帧，合计 4,765 帧。
当前采样范围没有三角形翻转；数值与非空、未裁切检查通过。

三角色 Setup 栅格对照最大 PMA 通道差为 3 / 5 / 2（0–255）。
红美铃仍有 5 个低透明边界像素跨过可见阈值，小恶魔与辉夜为 0；不能宣称逐像素完全一致。
15 个辅助链根点中 1 个缺少上衣重叠支持。整角色连接与视觉验收仍未完成。
机器证据见 [五层候选验证](benchmark/character-skirt-candidates-v1.json)。

红美铃实际工作台任务已验证构建、时间轴报告、完整下载及下载库存一致性。
本地文件页面被浏览器工具策略拒绝，因此没有宣称完成真实浏览器拖动操作验证。
Web 交互测试和已生成的官方 Runtime 帧分别作为交互逻辑与渲染证据。

## 开发接口

版本中立核心位于 `asset/planning/skirt_mesh.py`，合同为 `autospine.skirt-mesh-candidate/v1`。
JSON Schema 与来源重放 validator 分别检查结构和完整几何/权重语义。
Spine 转换、alpha 接触和复核页分开实现，新文件均低于 300 行。

普通工作台请求只需额外传 `skirt_profile: fixed-waist-three-chain-v1`，自动发现当前可用裙装图层。
未传参数时保留原有行为。诊断工具 `tools/build-character-skirt.py` 可对确切角色包和指定图层重复构建。

下一步验证重点为腰部与上衣动态接缝、裙面与腿部遮挡，以及支持不足根点的约束。
这些问题未解决前，不把五层新网格计入“已复核绑定”，也不据此提高整角色完成率。
