# M4 执行目标：从可导出到动作可用

2026-09-22，结合用户反馈与当前证据重新分解。本文件为当前执行顺序；m4-quality-delivery-plan.md 保留实验经过，不再以其中历次“下一步”作为并行任务。

## 现状与交付目标

FBX/BVH/Kimodo → MotionIR → 整角色候选 → Runtime → 导出的基础链路已经建立。外部动作的可靠表达尚未完成：原三角色 breathing 有阶段接受记录，其余新策略仍需对应候选的验收。历史整角色接受不自动转移到新动作。

下一个可交付里程碑为 **M4.1：三角色的 Reach／Squat 可用动作闭环**。固定 Alice、辉夜、红美铃，共六项。用户在一个页面观察源动作与角色的同一时刻，默认得到支持范围内的候选，只处理异常，并能导出所见版本。

不承诺仅凭正面立绘还原任意三维转身。需要侧背面或新遮挡内容时，明确请求姿态素材；风格化改编单独标记，不能称为原动作还原。

## 工作包与完成条件

| 顺序 | 工作包 | 交付及完成条件 |
| --- | --- | --- |
| 1 | 固定六案例与统一观察入口 | 来源、视角、参考姿态、策略、候选及采样清单固定；源正侧视和最终角色同时间播放；记录失败部件与时间。复用现有播放器，不新建分散操作入口。 |
| 2 | Reach 动作方向与连续性 | 保留举手方向、进度和左右手身份；退化投影使用深度和邻帧决定分支。消除非源动作引入的半圈跳变；不能靠冻结、删帧或隐藏限幅通过。 |
| 3 | Reach 前后关系 | 先完成在制的最小渲染分区：验证分区前后同帧像素、权重、UV、形变保持一致，再加入局部排序。混合前后区域不能强行整层排序；近面歧义保留异常，检查排序切换闪跳和肩缝。 |
| 4 | Squat 动作意图与支撑 | 先验证膝盖向前、手臂轨迹、骨盆下降及支撑脚，再处理视觉形变。正面投影不以膝盖屏幕位移代替前向深度；必要时使用明确声明的斜视或风格化表达。 |
| 5 | Squat 弯曲质量 | 区分正常投影缩短与额外挤压；局部 corrective 不可行时改用截面／辅助骨或姿态附件。保留原 setup 检查，新增投影评价单独报告，不放宽旧门槛掩盖失败。 |
| 6 | 工作台闭环与六项验收 | 同页提供动作、时间轴、异常定位、候选对照、重建及撤销；播放、报告、导出身份一致。六项在声明范围内技术通过且阶段视觉可接受，三项 breathing 无回归。 |

工作包 3 不能无限挤占工作包 4：当前三角形轨迹提取已完成，接下来只做一次保形分区和局部排序可行性验证。若仍无可播放改善，记录具体表达限制，保留该失败项，并推进 Squat；不能以更多诊断报告替代交付。

## 验收口径

- 动作意图：方向、时序、左右侧、支撑与来源一致；有意改编需明确展示。
- 时间连续性：源帧、必要中点、排序切换与求解新增时刻统一检查；播放器可定位并复现。
- 视觉：连接、轮廓、弯曲和前后遮挡整段检查；Runtime 数值通过不能代替视觉通过。
- 技术：有效网格、权重与纹理，保留各项失败记录。导出目标 Spine 4.3.26 与当前捕获 Runtime 4.3.13 分别注明。
- 泛化：同一策略用于三角色，算法不得按角色名、图层编号或三角形编号写特殊分支。
- 六项均留在统计分母，分别标记完整支持、受限支持、需补素材、失败；仅分类完成不能宣称 M4.1 完成。

## 随后两个里程碑

**M4.2 自动适配与异常恢复。** 将 M4.1 验证过的策略作为默认流程：动作导入／生成 → 能力分析 → 自动适配 → 异常定位 → 修改与重建 → 导出与恢复。普通归属按已授权默认采用；只有缺少必要信息时请求用户输入。三角色分别走通完整操作，人工决定与历史候选可恢复。

**M4.3 冻结策略与推广。** 冻结策略后重验三角色八动作 24 项，再扩展固定十角色。统计动作支持率、技术通过率、阶段接受率、人工干预次数、实测人工时间、自动耗时和 Runtime 失败率；错误自动采用率只以实际抽查为分母。失败和缺素材项不得移出集合，采用旧证据与重新捕获分别记录。

完整三渲二、脸部参数化、发型次级运动和更深袖装模拟作为后续能力包。当前可利用三维深度、朝向和弯曲平面改善二维表达，但不启动完整三维角色重建。

## 当前证据与工程约束

三角色 Reach 新躯干投影各通过 817 个时刻的原 setup 几何及 Runtime 数值检查，尚未全段视觉接受。Alice 匹配投影后的遮挡检查为 333/482 个歧义样本，149 个统一前侧样本，未测量为零；整层排序无可用候选。参见 benchmark/m4-reach-torso-cohort-v1.json、benchmark/m4-reach-torso-depth-v1.json。

每切片交付可播放改善或明确改变实现路线的证据。相同算法连续两轮没有实际改善，停止调参，转向拓扑、表达能力或素材诊断。模块按来源、投影、支撑、变形、遮挡、验证、UI 分开；遵守现有文件长度约束。保留在制代码和历史实验，未经验证不默认接入生产流程。

### 局部分区验证结果

Alice 双臂各 241 个源帧／中点轨迹已提取。保留原三角形顺序、仅合并兼容签名后，分区从 416 个降到 218 个（46 + 172），超过当前 128 个预算；左臂仍有 17 个三角形×时间混合深度样本。此数字不是全局最少分区数，也不是 17 个独立视觉缺陷。此次未生成候选、未运行新 Runtime、未更改正式排序。证据见 benchmark/m4-reach-trace-partition-v1.json。

不通过提高预算继续扩张此次实验。按前述切换条件，下一工作包推进 Squat 的源姿态、膝前向深度和支撑一致性；Reach 的拓扑与近面表达限制继续保留在六案例待办中。

### Squat 源姿态核对

新增独立的骨架端点检查，按目标 setup 的肢段长度归一化源 3D 向量，再比较投影与候选的实际关节原点。三角色当前实验候选各 57 个源帧，双臂端点误差均低于 1e-12 链长，说明这些版本已保留举手方向；不证明袖布／手部纹理的视觉位置正确，也不回溯否定用户在旧版本中的观察。

三角色双膝均无屏幕弯曲方向反转；每角色左腿 7 帧、右腿 6 帧的弯曲主要隐藏在深度方向。相机深度不能直接命名为解剖学前向。腿部支撑修正后的端点与源投影存在偏差：Alice 左／右最大 8.72%／7.18%，辉夜 9.74%／8.36%，红美铃 15.34%／7.41% 腿链长度。此处只检查源帧骨架，不包含中点、网格、裙腿遮挡或视觉验收。

证据见 benchmark/m4-squat-pose-fidelity-v1.json。下一步以 Alice 0.866667 秒、辉夜 0.9 秒、红美铃 0.966667 秒为定位点，检查支撑修正与变形之间的冲突，保留已经匹配的手臂轨迹，不重新盲调其旋转。

### 支撑求解端点保护

原窗口求解只优化骨轴方向；新增显式启用的逐时刻、逐腿髋脚相对端点保护，避免方向改善却使腿链末端更偏离源投影。脚部接触、根位移、旋转幅度和速度门槛保留，旧默认策略不变。检查时刻随实验报告保存，独立 FK 复核同一清单。

在原支撑任务的最差方向窗口各检查 65 个时刻，Alice 和辉夜得到候选，独立回放端点误差无增加，接触及运动限制通过。窗口峰值端点偏差分别为 23.335→23.243 px、37.724→37.557 px；这只是小幅改善，不能称为深蹲视觉修复。红美铃没有满足全部约束的解，返回原轨迹，求解器较低损失不能作为通过依据。三个窗口未完成整段网格重建和新 Runtime 验收，均未采用；见 benchmark/m4-squat-endpoint-guard-v1.json。

下一步不继续仅调方向目标权重；应在保持该保护条件下处理投影缩短与网格截面的表达，并完成实际同帧纹理对照。本轮尚未交付新的可视化对照窗口。

### 三角色同帧纹理对照已交付

集中入口为 http://127.0.0.1:14703/squat-stages-v1/ 。使用已有同步播放器，选择角色与阶段，比较“源投影 → 当前实验候选”或“支撑后未修网格 → 当前实验候选”。每个角色的三个阶段使用共同的相机范围，避免自动取景误导位置与大小比较。源投影仍使用原 2D 素材，不是源 3D 人物渲染。

六个中间阶段各新捕获 113 帧（源帧与中点），共 678 帧官方 Runtime 数值通过；三个最终实验候选复用此前精确身份的捕获，不冒充新捕获。六组播放器的同步、播放暂停、回拖恢复及参数定位检查通过。具体身份见 benchmark/m4-squat-stage-players-v1.json。

观察 1.12 秒实际纹理画面：双手已举起；Alice 肩部连接仍异常，红美铃膝腿轮廓在修正后仍不自然；辉夜长裙遮挡了腿部，不能据此判定腿形通过。本次提供诊断对照，不是新修复，也没有新增视觉接受。下一步应针对红美铃外露腿部验证投影截面表达，同时单独处理 Alice 肩部连接；不再把这些画面问题误报为手臂未举起或单纯角度换支。
