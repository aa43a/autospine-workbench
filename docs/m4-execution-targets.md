## 现状与交付目标

FBX/BVH/Kimodo → MotionIR → 整角色候选 → Runtime → 导出的基础链路已经建立。外部动作的可靠表达尚未完成：原三角色 breathing 有阶段接受记录，其余新策略仍需对应候选的验收。历史整角色接受不自动转移到新动作。

下一个可交付里程碑为 **M4.1：三角色的 Reach／Squat 可用动作闭环**。固定 Alice、辉夜、红美铃，共六项。用户在一个页面观察源动作与角色的同一时刻，默认得到支持范围内的候选，只处理异常，并能导出所见版本。

不承诺仅凭正面立绘还原任意三维转身。需要侧背面或新遮挡内容时，明确请求姿态素材；风格化改编单独标记，不能称为原动作还原。

### 表达策略与能力边界

自动适配按以下层级选择，保留采用原因与撤销入口：

1. 正面可表达动作：现有骨骼、权重与局部 corrective。
2. 明显纵深动作：使用三维朝向、弯曲平面和投影缩短作为证据；对明确的风格化投影单独标记，不伪称忠实还原。
3. 大弯曲或前后面切换：使用受控辅助结构、局部拓扑或有素材支持的姿态附件。附件切换需检验接缝、时序与闪跳。
4. 缺失侧背面内容：标记需要补素材；保留原动作和失败时段，不默默裁剪幅度。

角度展开只能处理表示上的周期跳变，不能解决真实手臂穿身、纹理前后面或任意 360° 转动。三维代理可辅助方向、深度和轮廓约束；完整三渲二角色重建不作为本里程碑的隐含前提。

## 验收口径

- 动作意图：方向、时序、左右侧、支撑与来源一致；有意改编需明确展示。
- 时间连续性：源帧、必要中点、排序切换与求解新增时刻统一检查；播放器可定位并复现。
- 视觉：连接、轮廓、弯曲和前后遮挡整段检查；Runtime 数值通过不能代替视觉通过。
- 技术：有效网格、权重与纹理，保留各项失败记录。导出目标 Spine 4.3.26 与当前捕获 Runtime 4.3.13 分别注明。
- 泛化：同一策略用于三角色，算法不得按角色名、图层编号或三角形编号写特殊分支。
- 六项均留在统计分母，分别标记完整支持、受限支持、需补素材、失败；仅分类完成不能宣称 M4.1 完成。

## 随后两个里程碑

**M4.2 自动适配与异常恢复。** 将 M4.1 验证过的策略作为默认流程：动作导入／生成 → 能力分析 → 自动适配 → 异常定位 → 修改与重建 → 导出与恢复。普通归属按已授权默认采用；只有缺少必要信息时请求用户输入。三角色分别走通完整操作，人工决定与历史候选可恢复。

**M4.3 冻结策略与推广。** 冻结策略后重验三角色八动作 24 项，再扩展固定十角色。统计动作支持率、技术通过率、阶段接受率、人工干预次数、实测人工时间、自动耗时和 Runtime 失败率；错误自动采用率只以实际抽查为分母。失败和缺素材项不得移出集合，采用旧证据与重新捕获分别记录。

完整三渲二、脸部参数化、发型次级运动和更深袖装模拟作为后续能力包。当前可利用三维深度、朝向和弯曲平面改善二维表达，但不启动完整三维角色重建。

### Squat 源姿态核对

新增独立的骨架端点检查，按目标 setup 的肢段长度归一化源 3D 向量，再比较投影与候选的实际关节原点。三角色当前实验候选各 57 个源帧，双臂端点误差均低于 1e-12 链长，说明这些版本已保留举手方向；不证明袖布／手部纹理的视觉位置正确，也不回溯否定用户在旧版本中的观察。

三角色双膝均无屏幕弯曲方向反转；每角色左腿 7 帧、右腿 6 帧的弯曲主要隐藏在深度方向。相机深度不能直接命名为解剖学前向。腿部支撑修正后的端点与源投影存在偏差：Alice 左／右最大 8.72%／7.18%，辉夜 9.74%／8.36%，红美铃 15.34%／7.41% 腿链长度。此处只检查源帧骨架，不包含中点、网格、裙腿遮挡或视觉验收。

证据见 benchmark/m4-squat-pose-fidelity-v1.json。下一步以 Alice 0.866667 秒、辉夜 0.9 秒、红美铃 0.966667 秒为定位点，检查支撑修正与变形之间的冲突，保留已经匹配的手臂轨迹，不重新盲调其旋转。

### 支撑求解端点保护

原窗口求解只优化骨轴方向；新增显式启用的逐时刻、逐腿髋脚相对端点保护，避免方向改善却使腿链末端更偏离源投影。脚部接触、根位移、旋转幅度和速度门槛保留，旧默认策略不变。检查时刻随实验报告保存，独立 FK 复核同一清单。

在原支撑任务的最差方向窗口各检查 65 个时刻，Alice 和辉夜得到候选，独立回放端点误差无增加，接触及运动限制通过。窗口峰值端点偏差分别为 23.335→23.243 px、37.724→37.557 px；这只是小幅改善，不能称为深蹲视觉修复。红美铃没有满足全部约束的解，返回原轨迹，求解器较低损失不能作为通过依据。三个窗口未完成整段网格重建和新 Runtime 验收，均未采用；见 benchmark/m4-squat-endpoint-guard-v1.json。

下一步不继续仅调方向目标权重；应在保持该保护条件下处理投影缩短与网格截面的表达，并完成实际同帧纹理对照。本轮尚未交付新的可视化对照窗口。

### Squat 肩部方法迁移

已将现有肩部边界方法复用于 Alice 的精确深蹲候选，保留此前全部 2,046 个检查时刻，新增检查后共 4,090 帧官方 Runtime 数值通过；骨骼动画、纹理、未选中部件及远端固定顶点不变。边界约束点最大偏差从 86.451 px 降至 0.144 px。

这版仍不采用：左肩层 layer-004 在 33 个初始求解时刻均有局部面积或边长失败，密集失败超过自适应 257 点预算；两个已有腿部失败也保留。1.12 秒实际对照中肩部位置靠拢，但袖口轮廓受到挤压，不能将边界接近视为视觉通过。对照入口 http://127.0.0.1:14703/squat-shoulder-v1/comparison/ ，身份与失败摘要见 benchmark/m4-squat-shoulder-v1.json。

同时修复 Runtime 捕获的传输限制不一致：Python 原已允许 256 MiB 解压数据，Node 现接收相同上限的输入，并保留 256 MiB 解压输出限制及未压缩输出检查。实际约 106 MiB 压缩文件已成功捕获，未减少任何检查时刻。

下一步需解决左肩受限边界内的形状／截面表达，不能仅增加采样或提高位移预算；右肩通过不能替代左肩和腿部验收。

### 左肩固定边界可行性实验

新增独立硬约束形状求解，保持原固定顶点、源位移预算、面积和边长门槛。Alice 左肩 0、0.866667、1.12 秒均未找到可行解；失败时返回原候选点，不将求解器的未通过形状写入动画。额外的固定顶点最短网格路径上限检查未发现矛盾，因此不能称为已经证明无解。

该结果与上一轮软约束结果共同说明：在固定接触点不变的情况下，继续增大求解次数没有已证实收益。下一切片改为验证“接触区域约束”能否替代过强的逐点固定：边界允许在有源 alpha 支持的接触范围内调整，远端、原纹理与位移预算保持；必须同时复核接触与轮廓，不能凭点距变小采用。若仍无改善，转向姿态附件／素材需求，不无限增加自由度。证据见 benchmark/m4-squat-shoulder-shape-v1.json。

### 膝部旋转插值路线已排除当前版本

新增独立实验：将旋转与正定拉伸分开插值，按实际相邻父子骨选择膝或踝的中心，保留骨骼轨迹及原素材。两个定位试验均未达到无回归要求。最终版本在 0.966667 秒右/左腿仍有 3/6 个翻转，1.12 秒左腿有 2 个翻转，比上一横截面实验更差；所有剩余翻转均处于 thigh/calf 混合区域，而非踝部。未发布新候选、未运行新 Runtime，也未改变默认策略。

单个顶点的插值矩阵保持正向，不等于由不同权重顶点组成的三角形保持正向。测试补充此反例，防止未来把矩阵行列式通过误报为网格通过。证据见 benchmark/m4-squat-pivot-blend-v1.json。

按两轮止损规则，停止该插值策略调参。下一有效路线应改变膝部材料的局部参数化／拓扑，直接控制内外侧弯曲轮廓并保留边界连接；仍先做有限关键姿态验证，不为已经失败的方案增加捕获帧数。

### 连续弯曲带验证与表达路线切换

按 setup 中混合权重区域和网格间距自动确定膝部带宽，测试了端点/切线连续的 Hermite 弯曲带，以及端点曲率为零、横截面跟随中心线的五次曲线。两种方案都保留骨骼轨迹，均在红美铃最低点增加翻转，未发布候选或新增 Runtime 捕获。

五次曲线方案在 0.966667 秒右/左腿有 14/15 个翻转，连续映射在 9/11 个顶点位置的两个差分步长下均出现负 Jacobian。它说明当前映射本身发生局部折叠，不能仅靠加密三角形修复；不证明所有连续网格方法不可行。证据见 benchmark/m4-squat-joint-strip-v1.json。

停止上述两种连续弯曲带的调参。下一切片转向“分段近端/远端表面 + 有源素材支持的关节覆盖区”，允许深度弯曲处合理重叠。必须先验证 setup 原图重建、纹理覆盖、动态接缝和绘制顺序；不能靠删除关节像素或伪造侧面素材通过。仍以红美铃外露腿验证，再迁移三角色，最终回接默认动作适配。
