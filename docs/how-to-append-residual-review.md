# 追加已检查的残余排除

在整角色预览的最终残余排除或拆分后残余排除中，已有清单不再阻止继续选择
新出现的静态残余。检查候选后，勾选新区域并点击“追加所选残余，保留已确认项”，
然后按原方案重建整角色。原素材、旧候选和旧确认版本均保留。

追加只适用于当前候选精确等于原排除清单执行结果的情况。系统重新执行原清单，
逐字节比较完整候选，包括纹理、骨骼、动画和构建证据。来源、构建方案、确认版本
发生变化时拒绝追加，不把旧确认套用到不同资产。需要先解决来源变化。

追加生成下一个清单版本，原决定保持不变。当前“撤销最终排除”撤销整份活动清单，
不是只撤销最后追加的一项。保存排除不代表通过动作视觉验收或获得发布权限。

API：向已有 `final-regions` 或 `post-component-regions` 端点提交 `action: append`，
其余字段与 `replace` 相同：当前 head、job、artifact 和新选择的 regions。
只提交新增区域；重复区域、超过 64 项、版本冲突或非精确来源均拒绝。

幽幽子的实际验证中，右袖残余共 346 个非透明像素，仅一个像素 alpha=11/255，
其余均低于 8/255。它没有被降低阈值自动排除；在用户明确确认后，追加到原四项清单。
网格中心覆盖检查只能说明位置支持，不作为像素归属或视觉通过证据。

部件绑定重建允许一种受限沿用：若上游仅更新构建凭据，而骨骼、所有动画、
贴图、数值参考及其他非元数据文件逐字节一致，同时图层清单和其余来源身份
保持一致，则复用原部件绑定并写入独立沿用凭据。原人工决定不被改写。
缺失核心证据、实际动画/贴图变化或角色来源变化仍然阻塞。
