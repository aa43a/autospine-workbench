# M6：完整制作流程

目标：从分层 PSD 或已有角色、动作文件或 Kimodo 描述出发，在同一任务中完成来源准备、默认绑定、整角色组合、身体动作、脸部/头发/服装联合动画、Runtime 检查、阶段验收和 Spine 候选交付。

默认采用有依据的已有策略；异常允许修改和撤销。技术检查、人工视觉接受、发布授权是不同状态。未抽查项不是人工正确标签，等待时间不是人工有效操作时间。

## 开发顺序与验收

1. **持久总任务**：每一步记录输入版本、子任务、结果和恢复状态。刷新不能重复提交；中断后恢复原任务或明确重试失败步骤。先贯通已有整角色，再接新 PSD 与新动作。入口集中在自动制作页面。
2. **异常回流**：定位角色、图层、区域、动作时间与联合动画控制；保留未修复异常，只重建依赖变化的下游。原候选与历史验收保留。
3. **批次与交付**：角色 × 动作批次、集中验收和下载；仅当骨架、皮肤、网格、纹理及动画目标兼容时合并多动作 Spine 包。不能直接拼接不同网格的动画。
4. **新素材验收**：冻结策略后选择未用于调参的三类角色完成流程；分别记录自动完成、人工修正、不支持和失败。记录真实操作时段与构建耗时，不能补算历史耗时或宣称未抽查项正确。

## 当前实现范围

`/production.html` 已串联来源准备、默认安全绑定、整角色、身体映射、M5、现有 Runtime 和最终阶段复核。已有整角色直接复用。页面也可导入 PSD / 动作文件或提交 Kimodo 生成；来源任务提交后，可在“来源完成后自动制作”选择尚在解析或生成的来源，保存持久衔接任务，无须保持浏览器打开。现支持持久批次、兼容性检查及多动作合包服务；完整异常回流及冻结新素材验收仍待完成，M6 尚未完成。

每个任务保存不可变修订；先写子任务预留身份，再调用现有构建服务。恢复时检查这个确切身份，避免在请求已保存、父任务尚未更新的窗口重复创建子任务。跨进程执行租约避免两个协调器同时执行同一总任务。

身体与联合动画构建成功后进入阶段验收；仅读取联合动画自身的现有验收记录，不沿用身体或整角色的接受记录。候选下载保留原有技术异常检查与证据。

服务停止时总协调器先退出，子任务由各自管理器关闭。服务恢复后在制作页继续任务；子任务若中断则显示需干预，可明确重试，并保留旧尝试身份。候选来源变化时阻止续用旧输入。

“按当前角色修正重建”创建新总任务并保留父任务身份。来源与身体设置不变时复用身体子任务；联合动画重新生成，并重新要求自己的阶段结论。已有人工绑定、排除和路线选择由原服务保留。

## 持久批次与覆盖回流

制作页新增批量勾选角色与源动作，按当前观察角和联合动画设置创建最多 32 个组合。批次在调度前保存全部输入和总任务身份；恢复时只使用对应身份。某个组合失败或需要人工输入时，其他组合继续。停止批次只停止后续调度，已有或共享的总任务可以在各自页面取消；不会因停止批次而取消其他用途的候选。

`/api/production-batches` 保存不可变批次修订，支持读取、继续和停止。每个组合可在同页查看其制作链和播放器。重建后需要使用新输入创建新批次，旧批次不悄悄替换版本。

合包前检查读取当前候选实际数据，以角色和完整绑定结构分别分组：骨架 setup、slot 顺序、skin/mesh/UV/权重、约束、atlas 和图片内容都必须一致，仅忽略描述性 skeleton.hash 与各自动画内容。相同骨名或文件名不足以兼容。`can_merge` 仅表示结构上可进入合包验证；实际结果必须重新捕获 Runtime。

制作页同时提供逐层覆盖摘要，保留静态参考和缺失区域。妹红目前 21 层中 3 层含未绑定区域：back hair、legwear、topwear。构建成功不等于这些层已绑定，也不等于动作或视觉通过。

## 来源到制作的持久衔接

`/api/production-entrances` 连接已有角色或 PSD 导入任务，与上传/生成动作任务。提交时冻结来源请求身份和制作设置，预留总任务身份；PSD 或动作尚在处理时等待，失败时保留原因。两项完成后先保存确切制作请求，再提交预留总任务；当前输入完全一致的既有任务可复用。重复请求、刷新和服务恢复不会另建制作任务。输入变化时明确阻止续用旧来源；既有总任务一旦交接，就由原有重建策略管理后续版本。

来源列表来自服务端持久任务，可找回此前上传/生成记录，不依赖页面 localStorage。取消衔接不会删除或取消共享来源任务；交接后应在制作任务中取消。服务重启后点击继续衔接，旧来源失败可选择新来源重新建立关联，旧记录保留。

## 制作任务计时与统计

制作页增加任务级人工秒表：明确开始、暂停并保存，可撤销；切换任务、离开或隐藏标签页会暂停，草稿在本机浏览器暂存并以暂停状态恢复。服务器记录绑定确切 run 和请求身份，拒绝重叠、重复、冲突、任务创建前或未来的时段。它与已有项目级计时分别展示，不重复相加。测试操作没有写入真实人工记录。

`/api/production/{run}/work-sessions` 为不可变计时日志，`metrics` 分开给出人工已记录时长、任务经过时长、子任务预留到观测结束时段，以及子进程已经记录的实际执行经过时间。执行时间包含 I/O 和 Runtime 捕获，不是 CPU 时间；未记录的步骤不补算，排队与等待不能通过简单相减可靠分离。阻塞记录和重试请求只是流水线事实，不记为人工干预次数。完整人工耗时、纯计算时间、独立等待时间保持未知，不能把没有计时解释为零人工。

## 同页异常定位与重建范围

制作页将联合候选和身体来源的检查分开显示，异常时刻与部件隔离可在独立的同页播放器定位。播放器必须与对应候选的 artifact 一致；一般进度轮询不会重置定位。联合动画缺测仍保持缺测，身体来源异常不会被联合动画的通过状态覆盖。

`revision-plan` 在创建任务前冻结输入、原修订与重建范围。相同角色和身体参数只重建联合动画；改变固定观察角重建身体和联合动画。当前角色已变化时显示换用当前已验证角色及受影响下游。历史任务缺少来源/绑定步骤记录时，以已验证整角色作为沿用依据，不将其误报为重新计算。执行时再次核对计划摘要，来源或参数变化会拒绝旧计划，不创建新任务；新任务不继承阶段接受。

## 身体修复版本回流

制作页的“修正后重建”可列出当前身体来源的登记候选，以及具有明确父子关系的已完成局部修复任务。选择后冻结原身体、所选修复、请求、候选产物和证据身份，再接入 M5 联合动画。角色/源动作/身体参数必须一致，修复任务须沿父子链返回本制作任务的身体来源；任一父级产物变化都拒绝采用。执行联合构建前再次比对所选来源。修改观察角需回到原身体路线重新生成，不能把旧角度修复嫁接到新动作。
