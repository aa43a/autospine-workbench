# 分类与批量预填图层绑定

在主工作台「可变形动画候选预览」展开「图层绑定复核」。

1. 用「绑定复核分类」筛选单骨、网格、分区、衣饰与次级运动、眼口或缺少方案的图层。
2. 在全部或单骨分类下，点击「预填待复核的单骨刚性建议」。
3. 查看各层及所选骨骼。预填只修改当前页面的草稿，可用「撤销未保存修改」恢复。
4. 检查后点击「保存绑定复核并重建」。这仍使用现有带来源校验的保存接口。

批量预填只消费已有的唯一单骨刚性建议；不会创造绑定选项，也不会覆盖已有 bind、exclude、requires_split 或 semantic_review 记录。
筛选仅影响显示，保存仍提交完整记录集合并保留说明。来源变化会清除旧来源的本地草稿；只读状态不能预填或保存。

分类依据是当前候选选项、原因码及源图层名称，是导航提示，不是新的语义分析或自动采用策略。
衣饰、头发、复杂物件、分区以及存在冲突的候选不参加刚性批量预填。眼口需先准备专用候选，再在眼口分类中单独预填；这不代表已经支持眨眼口型。
没有绑定选项时，保留待复核或填写进一步处理说明；不能将空选项保存成绑定决定。

## 补齐眼口候选

点击「补齐眼口绑定候选」，系统复用 `rigid-name-completion-v3`，为眼白、虹膜、眉毛、睫毛、鼻、嘴、耳朵及头饰中的受支持输入补充静态 head 绑定选项。
操作新增内容寻址候选及来源登记版本；不选择绑定、不授予生产权。来源已变化时拒绝更新，同一来源重复执行不会继续增加登记版本。
没有变化的已复核决定完整保留；如果新增选项会影响已有排除等明确决定，本次升级拒绝执行，原记录不变。

补齐后，选择「眼口细节待复核」，点击「预填眼口静态头部绑定建议」，检查对应图层后再保存。该按钮只消费带有 completion 证据的唯一 head 建议；一般名字相似的图层不会被直接批量绑定。
衣饰/分区继续保留待复核。后续关节编辑与主项目校正同步保留 completion profile，骨架几何变化仍将相关绑定退回待复核。

四个可见项目已准备：lumia/huiye/uuz 各 12 个选项，yaomeng 13 个（含头饰），共 49 个。准备前后的已保存记录逐条一致；Lumia 页面实测十二项预填和撤销，没有提交人工决定。
来源升级后，旧动画包属于历史来源，需要重新构建才能作为当前候选；之前 244 帧 Runtime 记录不能算作新包的验收。

验证：442 项 Web 测试通过；候选升级、幂等、来源冲突、关节与校正同步回归通过。HTTP 首轮一次本地连接中断，相关 HTTP/质量检查 7 项重跑通过。新模块保持在文件长度门禁内。
