## 使用

打开 `http://127.0.0.1:8918/motion-editor.html`：

1. 在“已有身体候选”选择构建成功的身体动作。若存在已登记的局部修正版，
   在“候选版本”选择对应版本，然后载入。来源角色、动作、视角和版本会一同核对。
2. 在“表情、发束与服装联合动画”启用需要的通道。
   面部支持自动眨眼、视线、眉毛、口型和有限五官偏移；手动表情关键帧优先于自动行为。
3. 放大面部画布可拖动眼口锚点；发束、裙袖可选择区域、修改强度、刚度、阻尼和角度上限。
   发根固定范围独立可调。支持撤销、重做和绑定到精确身体版本的本地草稿。
4. 构建联合候选。参数改动后，画布仍明确标识为上次构建结果；再次构建才更新最终烘焙。
5. 在共用时间轴播放或倒拖实际导出结果，查看异常和各区域保护后的实际强度。
   “下载 Spine 候选”获得一个直接包含联合动作的 Spine 4.3.26 包。

从集中页点击“重新编辑”可恢复该联合候选的原始配置和精确身体版本。
也可使用 `motion-editor.html?joint=<joint-job-id>`；页面会核对来源和配置摘要，
参数修改后提示与已构建结果不一致，撤销后恢复匹配状态。

新的联合包不覆盖身体候选。修改身体或其局部修复后，应从新身体版本重新构建联合动画；
旧身体修复入口不会对联合包静默执行一个被忽略的修复。

## 已实现能力

| 部分 | 实际行为 |
| --- | --- |
| 来源 | 主候选与已登记 related candidate 均绑定精确 artifact、原请求、来源与角色；重试继续核验 |
| 面部 | 从原图层建立眼白/虹膜/睫毛/眉毛/嘴部控制骨；同步显隐；保留原动画与已有 deform |
| 基础口型 | 原嘴形控制、可选程序绘制开口模板、可导入 64×48 RGBA PNG；保存原字节和摘要 |
| 发束 | 基于 alpha 的网格、固定发根、辅助链、身体运动驱动的确定性响应 |
| 裙袖 | 复用已有辅助链和权重；固定腰部/袖口边界；保留原修形；识别并移除旧正弦测试轨道 |
| 防变形 | 只衰减新增响应；检查网格与头身二维代理新增穿入，必要时单独关闭异常区域 |
| 交互 | 四类时间轨、手动表情键、局部参数、锚点拖动、撤销/重做、草稿保存和恢复 |
| 导出 | 一个可播放的组合动作；主 JSON 与 `editor/skeleton.json` 同步，所需图片一起打包 |
| 检查 | 身体保持、固定根、网格、接触、已有遮挡检查、新增循环、官方 Runtime 和导出回读 |

本实现没有引入 Anime2.5DRig 的独立渲染器；全部新增动画烘焙为 Spine 骨骼、
加权 mesh 和 alpha 轨道，不依赖编辑页 JavaScript 才能产生效果。

## 支持边界

- 首批固定集是 Alice、辉夜、红美铃的呼吸与挥手，共六份；已接受的行走修正版为扩展检查。
- 眼睛使用原睫毛压缩及眼白/虹膜同步隐藏；没有宣称生成角色原画级闭眼差分。
  开口模板也不是音素同步，替换图需保留角色画风并做外观复核。
- 小幅五官偏移不是完整头部转向重建；视线为保守位移，没有逐像素眼窝裁剪。
- 发束/服装是离线有界弹簧，不是任意运动下的三维布料；碰撞只检查二维头身代理，
  不等同 alpha 遮挡、自碰撞或连续时间保证。相机连续旋转且无法分离身体惯性时，会阻止新增响应。
- 几何保护后的响应可以小于请求值，甚至为零；页面逐区域显示，不能将被关闭区域计为已应用。
- 固定步长约 120 Hz，普通效果键约 60 Hz，必要转折保留 120 Hz 键。
  原身体关键帧与 QA 点保留；超过 4,097 个联合检查点时要求缩短片段，不删除证据点。
  早期草稿的 `fps`、`seed` 字段为兼容性保留，不作为当前可调求解频率或随机效果开关。
- 当前只支持单 skin、单身体动画；已有附件切换等不兼容表示会明确列出，避免错误合成。
- M4 原有遮挡缺测、素材散点和身体循环速度接缝继续保留。新增效果通过不会清除这些记录。

## 验证与复现

工作台的真实提交/轮询/捕获流程可由以下命令复现：

```powershell
$env:PYTHONPATH='src;tools;tests'
python tools/check_joint_animation_job.py <body-job> --output tmp/m5-joint/result.json --loop
# 使用已登记修正版：
python tools/check_joint_animation_job.py <body-job> --registration <registration-sha256> --output tmp/m5-joint/related.json
```

`--loop` 只用于确需循环的来源；检查会分别输出原身体、新增 helper/显隐及最终整体结果。
不会强行把非循环身体轨道改为循环。

集中阶段复核页由 `tools/build_m5_review.py` 从精确六个联合 job 生成，使用官方播放器。
页面支持角色/动作选择、时间轴、技术摘要和包下载；本地视觉草稿没有自动提升为服务端接受。
最终固定候选、测量结果和验收状态记录在 `docs/benchmark/m5-joint-delivery-v1.json`。

浏览器集成证据保存在 `tmp/m5-joint-live-e2e/`、`tmp/m5-joint-related-e2e/`、
`tmp/m5-joint-reopen-e2e/` 与 `tmp/m5-joint/final-review/browser-check/`：
真实身体载入、口型 PNG、锚点拖动/撤销、局部参数、提交、播放、正反定位和下载已实测。
身体修正版另在主工作台 8918 实测，不使用模拟响应。

完成标准是代码、可用入口、准确导出及技术证据齐全，再记录新联合结果的阶段视觉判断。
构建成功或旧 M4 接受不自动代表 M5 视觉接受。
