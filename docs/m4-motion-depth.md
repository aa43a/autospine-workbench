# 外部动作深度诊断

新角色适配请求记录 `external-arm-torso-depth-review-v1`。旧请求不增加深度文件、不更改重放身份。目标任务从已验证源包快照读取数据，生成 `motion-depth.json`，并把身份纳入候选文件清单。

BVH 使用既有三维 FK 的深度坐标，Kimodo 使用矩阵一致性校验后的 SOMA77 位置。当前视角 profile 明确约定映射深度正方向朝相机；来源字节、映射、角色、动作包和输出 skeleton 身份均保留。裁剪时保留原源帧编号，报告时间平移到目标片段起点。

根据有效网格权重识别左臂、右臂和直接胸部附件。混合归属、头颈、腿部、裙链和未知附件不推断成躯干。对肩、肘、腕相对源上躯干的深度建立配对证据，复用已有 Schmitt 迟滞：进入差值为源参考腿长 4%，退出差值 2%，连续三帧产生换序建议。单帧抖动不换序；同一手臂跨越躯干前后超过迟滞带时，保留原顺序并报告跨平面区间。

入口：**动作中心 → 新建角色候选 → 查看遮挡时间点**。报告把连续跨平面帧合并成区间，可以跳到同一候选的官方 Runtime 时间轴；完整 JSON 保留逐帧记录。结果说明源深度关系，不宣称目标像素重叠或最终遮挡已经通过。当前尚未写入动态 drawOrder。

- 三角色×八类动作共 24 项诊断、48 个换序建议；4,264 个跨平面的配对采样记录，不能把重复配对采样数当作独立错误数量。
- 辉夜抬臂读取已完成的精度参考重试产物，原失败基线保留；其余来自原固定基线。
- 新 Kimodo 挥手→Alice 任务 `motion-807411591e6d42cc90f68dcdd3f18c7b`：375 帧官方 Runtime 与几何通过，深度状态为 `depth_candidates_need_review`，未自动改变绘制顺序。

精确身份和各项候选事件见 [深度对照记录](benchmark/m4-depth-baseline-v1.json)。这些结果不代替目标像素遮挡检查或人工阶段验收。

下一步需要结合目标动画同帧附件重叠，过滤没有视觉交集的建议；对可整体换序的配对编译动态顺序并用 Runtime 检查，对跨平面的单附件保留分区异常。

## 同帧重叠与受约束顺序 v2

新任务现使用 `external-arm-torso-depth-overlap-v2`，v1 历史任务保持原行为。复用原纹理 UV、实际仿射变形和双线性 alpha，在源采样时刻测量附件像素中心交集；阈值为 8/255。单 ROI 上限 262,144 像素，总检查预算 64,000,000 像素操作。超预算或不支持的附件返回未测量，不能当作无交集。

动态顺序编译器检查源采样时刻和相邻中点。仅在可见重叠、源深度明确时提出前后约束；跨平面、有冲突的顺序、未知可见中间附件均拒绝。只有没有视觉交集的中间附件才允许跨越。所有采样约束通过后，才能在独立候选动画中写入 `drawOrder`，保留 setup slots、骨架、网格、纹理和已有角色身份；原动画已有顺序时不覆盖。当前策略是采样约束，不宣称连续时间或人工视觉通过。

工作台增加像素检查进度提示，报告展示有交集、跨平面、与原顺序不符及未测量计数；具体拒绝原因折叠展示并可定位时间轴。

真实检查：

- Alice 侧面行走：244 个可见配对采样，其中 38 个跨平面、120 个与原顺序不符，保留原顺序。
- Alice Kimodo 挥手：240 个可见配对采样，其中 217 个跨平面，没有明确换序要求，保留原顺序。
- 新正面行走任务：184 个可见配对采样，180 个与原顺序不符；77 个检查时刻存在未知可见附件顺序冲突，候选拒绝。原有几何失败继续保留。

官方捕获现在逐帧独立重建 JSON 绘制顺序，并与 `skeleton.drawOrder.appliedPose` 比对；Float32 时间边界单独处理。正面行走 377 帧全部一致，该任务没有采用动态改序，不能据此宣称修好了遮挡。另用官方 4.3.13 核心在 7 个边界时刻验证真实换序与恢复顺序。24 项 Python 测试及 Node 顺序重建测试通过。

精确身份和失败时间见 [同帧重叠证据](benchmark/m4-depth-overlap-v1.json)。后续需要处理可见中间附件的语义关系或分区，不能强行交换整张手臂来绕过它们。
