# M4 外部动作中心

目标：FBX/BVH/Kimodo SOMA77 NPZ 或文字生成 → 动作资产 → 视角适配 → 角色重定向 → 接触/几何/Runtime → 可播放、可导出的 Spine 4.3.26 候选。默认采用有效方案，只处理异常；保留人工决定和旧包身份。

## 交付顺序

1. 动作中心和持久化导入任务：FBX/BVH 上传、取消、重启恢复入口、源骨架时间轴、Mixamo 映射与 MotionIR。
2. 当前角色适配：复用既有投影缩短、仿射修正和接触检查；工作台免填 SHA 构建候选、定位异常、官方播放与下载。
3. Kimodo SOMA77 NPZ 导入和隔离生成任务：环境检查、模型/seed/请求身份、进度、取消与结果选择，复用同一动作资产链。
4. 三种结构角色 × 八类动作验收，再确认支持范围。建议角色为红美铃（无袖）、辉夜（宽袖长裙）、爱丽丝（普通衣装）；动作包括呼吸待机、行走、挥手、抬臂、转体、下蹲、拳击、伸手。越界必须说明原因，不能通过更换失败样本宣称全部通过。

## 当前已实现的切片

导航增加“动作中心”。上传原始 FBX/BVH，不接受客户端命令或服务器文件路径。FBX 使用服务端 `AUTOSPINE_BLENDER` 指向的 Blender，或 PATH 中的 Blender，隔离执行并检查逐帧 BVH 关节与源 FBX 的一致性。

自动映射当前覆盖 Mixamo 标准名称及 `mixamorig:` 前缀。界面显式选择正面（X/−Y）或侧面（−Z/−Y），使用原骨架腿段长度归一化；不推断未知坐标约定、接触或循环。未知骨架保留原文件及可读的源时间轴，返回映射待处理。

原始字节、转换 BVH、证据、映射和编译结果分别保存。重试新建任务，历史不覆盖；服务重启后未完成任务标为中断，可重新解析。后台超时或取消终止解码进程。源骨架显示最多 240 个采样姿态，完整源帧进入既有有界编译器。

动作中心可选择已有整角色候选，后台按精确动作与角色身份执行重定向、投影长度适配、有界混合权重局部修正和密集几何检查，继续调用既有官方 WebGL 捕获。只生成独立 `external-motion` 动画包；原角色的网格、权重、纹理、绘制顺序和历史动画不覆盖。

投影塌缩、长度范围超限、修正失败或几何不通过时，结果标记为诊断候选并列出原因，不把回退结果计为受支持动作。可打开官方 Runtime 时间轴和下载诊断包。来源变化时旧结果保持历史记录，打开、重试与下载会重新核对来源；需选择当前角色重新构建。

2026-09-20 已实测 `walking.fbx`（53 骨/32 帧）和 `boxing.fbx`（53 骨/67 帧）的全帧 FBX→BVH 一致性及 MotionIR 编译。Alice 行走候选通过 287 帧几何/官方 Runtime 检查，最大顶点误差约 0.000114 px。该记录不代替人工视觉验收、接触锁定和深度遮挡验证。

拳击→Alice 的 321 帧官方捕获完成，但正面投影存在骨段塌缩及一个变形失败记录，保持 `needs_changes`。这项不计为受支持动作，不用 Runtime 顶点一致性覆盖几何失败。

第二切片已接通 Kimodo SOMA77 NPZ。显式填写帧率，复用严格 NPZ/矩阵 FK 校验、接触标签编译和 MotionIR 精确读取。投影长度缩放复用同一父级补偿算法，直接读取经过矩阵验证的位置，不伪造中间 BVH。原始 NPZ 和已验收角色不改写，未附带的生成来源保持未知。

真实 `wave-left-v1` NPZ（77 骨、120 帧、30 FPS）通过新入口生成 Alice 候选；375 个密集采样通过几何和官方 Runtime 检查。浏览器已验证源与角色的 1.5 秒时间轴位置。见 [NPZ 交付记录](benchmark/m4-kimodo-intake-v1.json)。这不代替人工视觉验收或角色接触/遮挡验证。

第三切片已接通源接触标签驱动的踝部支点检查与有界根骨修正。修正保持单独候选并可关闭；半开支撑区间、双脚残差、修正位移/速度、过渡和修正后密集采样共同决定是否采用。报告可跳到异常时间点。真实 Alice 挥手的滑移峰值从 14.34 px 降到 0.73 px，375 帧 Runtime/几何通过，详见 [接触记录](benchmark/m4-motion-contact-v1.json)。这不证明鞋底接地、地面碰撞或无标签 FBX 接触正确。

第四切片已接通本地 Kimodo 文字生成。请求字段有界、进程隔离、离线模型校验、取消、重试和重启中断恢复入口均复用动作任务队列。每任务派生文本适配器避免共享目录权限问题；原始模型保持不变。真实新生成的 4 秒/100 步/seed 42 挥手得到 77 骨/120 帧，复用 NPZ/MotionIR 后生成 Alice 候选，375 帧几何和官方 Runtime 检查通过。详见 [生成记录](benchmark/m4-kimodo-generation-v1.json)。尚未进行人工视觉验收。

第五切片接通正面/侧面重新投影与帧对齐裁剪。新视角保留相同原始字节与生成来源；裁剪保留原始绑定相对值、截取接触区间，并以原绑定网格检查几何。修复了“动画第 0 帧等于绑定姿态”的历史捕获假设，非静止起点增加独立 setup 捕获。真实 Alice 挥手第 31–91 帧形成 2 秒候选，345 帧 Runtime/几何通过，见 [视角与裁剪记录](benchmark/m4-motion-selection-v1.json)。

M4 尚未完成：无标签动作接触处理、动态遮挡、超出正面/侧面的视角适配及固定三角色八类动作验收仍需继续。生成成功不计作任意角色或动作都受支持。

第六切片建立固定三结构角色 × 八类动作的可续跑验收与异常定位报告。完整呼吸待机已在 Alice、辉夜、红美铃分别完成 554 帧官方捕获及几何检查；其余组合继续运行，不计为已通过。计划、来源不一致处理和命令见 [固定动作验收](how-to-m4-motion-cohort.md)。

后续已定位行走正面投影塌缩，独立侧面 Alice 候选通过 377 帧数值/几何检查，但遮挡仍有异常。另新增 [Runtime 存储参考](runtime-storage-reference.md)，在不放宽门槛、不更改候选字节的前提下，复现并解释辉夜抬臂的 Float32 时间轴误差；313 帧重新对照通过，原有几何失败继续保留。

固定 24 项正面基线现已全部结束：23 项捕获完成、8,447 帧、11 项几何通过；仅 6 项无已记录候选异常，不代表可发布。投影诊断已进入工作台，新提交已启用 Runtime 存储参考。完整口径与分动作结果见 [基线结果](m4-fixed-baseline-results.md)。

无标签 FBX 已增加独立的低位静止踝部接触候选，七个固定来源完成诊断；行走与拳击仍缺静止支撑证据。此切片不自动锁脚，也不改写历史 MotionIR，见 [推断口径与结果](m4-inferred-contact.md)。

后续接通有源三维静止证据约束的默认自动修正：全片双脚符合条件、目标位移/速度/残差与密集网格检查均通过时，生成根骨加小幅踝端平移候选；否则回退。来源标签与历史候选不改写，待机三角色证据单独保存；动态遮挡、交替支撑与其他异常动作仍未因此获得通过结论。

后续修复向上轴与屏幕竖轴混淆，行走、拳击已获得支撑候选；逐区间累计位移及有界仿射腿链实验继续保留失败范围，不能沿用早期“无支撑证据”的结论。最新结果均见上述接触记录。

动态遮挡已进入新候选报告与工作台定位入口：三角色×八类动作生成源深度证据和迟滞换序建议，新 Kimodo→Alice 集成通过 375 帧 Runtime。当前尚未自动改变绘制顺序，下一步需要目标同帧重叠检查及可采用排序；见 [深度诊断与范围](m4-motion-depth.md)。M4 仍未完成最终支持范围和阶段验收。

v2 已接入同帧 UV/alpha 交集和受约束动态顺序编译，并在官方捕获中逐帧核对绘制顺序。真实行走与挥手存在跨平面或未知可见附件冲突，保留原顺序；正面行走 377 帧顺序核对通过，不代表原有几何或遮挡异常已经修复。最新细节见同一深度文档。
